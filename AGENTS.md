## Project

This repository is `agent-com`, the RFA (Rooms for Agents) hub and operator CLI. It is a TypeScript package whose source lives under `src/`. with CLI commands in `src/cli/commands/`, TUI components in `src/cli/tui/`, and eval harness in `src/evals/`. The package is built with `tsc` (configured by `tsconfig.json`) and publishes two binaries, `rfa` and `agent-com`, both pointing at `dist/cli/main.js`. Specifications live in `spec/`, research in `research/`, and operator-facing templates in `templates/`.

## Structure

Where the parts that matter live:

- `src/` - hub daemon, engine, CLI, TUI, and eval harness source; the only directory compiled by `tsc`
- `src/cli/commands/` - one file per CLI sub-command
- `src/cli/tui/` - Ink/React TUI components for the dashboard and onboarding
- `src/evals/` - eval runner, gate, judge, label, parity, promote, and trajectory modules
- `spec/` - all seven RFA specification documents that govern wire protocol, platform, CLI, concurrency, and egress
- `templates/` - files seeded into a new hub directory by `rfa init`, including the eval rubric and case stubs
- `test/` - all test files globbed by the `test` script
- `scripts/` - standalone runnable scripts for e2e, coldstart, demo, fence-proof, egress-proof, and TUI smoke
- `interop/` - the `rfa_min.py` minimal interop artifact
- `src/proc.ts` - required spawn helper; child processes must be spawned through this module, never via `npx`
- `src/writefence.ts` - keeps `Write`, `Edit`, and `NotebookEdit` out of `allowedTools` for every pack
- `src/fenceprobe.ts` - re-proves the fall-through with a live deny probe per guarded built-in at every boot
- `src/toolclass.ts` - defines `fenceApplies`, the coverage predicate for the two-door write fence
- `src/secrets.ts` - provides `transportToken()`, which resolves the transport credential; clients must call it per request, never capture at import

## Code Style & Conventions

- Spawn child processes through `spawnEntry` and `stopTree` in `src/proc.ts`, never `npx`; `spawnEntry` passes tsx's loader by absolute path because `--import tsx` resolves from the working directory
- Resolve the hub directory through `src/hubdir.ts` exclusively; no source file under `src/` may resolve `agents/`, `data/`, or `dogfood/` from the repository root
- Find a resident in the process table using `src/procscan.ts`, never a substring match
- The fence coverage predicate is `fenceApplies` in `src/toolclass.ts`, never `hasWriteSurface`; a pack declaring `Bash` is fenced for that reason
- A check that compares configured against happening must read the running system's own record, not the file the operator edited; honest sources are `state/member.json`, `runs.db`, and the supervisor's state
- One knowledge fact must live in exactly one file; check for duplicates before adding a source
- Never start anything interactive when stdout or stdin is not a TTY
- The `rfa evals parity` gate must be run twice; a single pass has hidden a real regression
- After changing `src/`, restart the affected long-lived process: `rfa agent restart <name>` for a resident, `rfa restart` for the hub and supervisor
- The `tsconfig.json` `rootDir` is `src` and `outDir` is `dist`; only files under `src/` are compiled
- The `tsconfig.json` target is `ES2022` with `module` set to `Node16`
- JSX is compiled with `react-jsx` as set in `tsconfig.json`

## Testing

- Unit tests run with `npm test`, which executes `node --import tsx --test test/*.test.ts test/*.test.tsx`
- The `pretest` script enforces Node.js >= 22 before running tests
- Test files live in `test/`
- A new test file in `test/` is picked up immediately by the glob without any registration step
- TUI changes additionally require `npm run tui:smoke`, which drives onboarding and dashboard inside a real pty
- Wire scenarios and CLI lifecycle are covered by `npm run e2e`, which writes output to `reports/latest.md`
- Deterministic concurrency ordering tests live in `test/interleaving.test.ts`, which drives every ordering with barriers
- Stress loops are kept out of `npm test`; nondeterminism belongs in an opt-in soak mode

## Boundaries

Things an agent must not do in this repository:

- This repository carries no instance: no `agents/`, `data/`, or `dogfood/` directories (all removed 2026-08-25)
- The hub must own its store (`<hub directory>/.rfa/data`) and its lockfile exclusively; `rfa up` runs one HTTP hub per directory
- The engine DB (`.rfa/data/runs.db`, WAL) is separate and shared by supervisor and residents; a resident's `state/member.json` spend is a mirror, never the source
- A writing pack that cannot establish both doors of the write fence refuses to serve rather than serving with one
- The fan-out for candidates is local: the room sees one task, one owner, one completion, and only a selected winner's answer is recorded as an episode
- `reports/`, `dist/`, and every hub directory's `.rfa/` are gitignored; never force-add them
- Every pack gets `view/create/insert/str_replace` on `/memories` and only those by default; `delete`, `rename`, and `str_replace` on `blocks/*` reach a pack only if its `tools.allow` names them
- A pack's MCP servers of the `command` and `builtin` forms are spawned through `src/mcplaunch.ts`; the `url` form stays unconfined
- A threshold tuned to suppress noise will hide a total outage; rates need volume guards and states need a direct check

## Gotchas

- Non-interactive shells default to fnm Node 20; the `pretest` script rejects Node < 22 with an explicit error referencing `STATUS.md`
- The `better-sqlite3` binding needs Node 24 per the `pretest` error message
- Never delete `dist/` without running `npm run build` after, since the linked `rfa` binary executes it
- Long-lived processes (hub, supervisor, residents) serve old code after an edit; restart them explicitly after changing `src/`
- Run `npm run fence-proof` after every SDK bump; door one of the write fence is version-fragile by design
- Run `npm run egress-proof` after every SDK bump alongside `npm run fence-proof`
- A bare `allowedTools` entry auto-approves a built-in call before the `canUseTool` callback fires; the SDK emits `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED` when this occurs
- A Read built-in inside the session cwd is auto-approved and never reaches the `canUseTool` callback; a Read outside it does reach the callback
- `allowUnsandboxedCommands` defaults to true, leaving `dangerouslyDisableSandbox` live; a model used it to escape into the pack tree on the first probe
- The supervisor is a hub client and must resolve its transport credential through `transportToken()`; it had no credential and its alerts 401'd silently
