## TL;DR

**The wave was commissioned as "reach and collaboration" and its own evidence retired half that title, so v0.5 is not a reach release: it is a trust release.** The two approval cards that died did not die because the hub was on localhost. They died because `src/bridge.ts:59` defaults an approval window to ten minutes and `src/resident.ts:388-394` then caps it at `reply_by - 30s`, while `src/store.ts:1968` sweeps the expired card to **`reject`**, so a clock produced a record indistinguishable from a considered human refusal [01]. Meanwhile the hub is already **not** on localhost: `src/main.ts:326` calls `server.listen(port, cb)` with no host argument, so Node binds `::`/`0.0.0.0`, and `GET /api/agents/<name>/definition`, `/api/approvals`, `/api/runs` and `/api/summary` all answer **without a token**, which means every network the laptop has joined could read the French Goodvest system prompt, pending draft documents, and run payloads [01]. The first thing v0.5 does is reduce exposure and stop the clock from forging refusals. Reach is one thin slice on top, not the theme.

**Three of the four mechanisms wave 02 deferred to v0.5 are ceremony at this scale, and the fourth turned out to be half-shipped in RFA's own code.** Flow-rule DSLs: the runtime half left open source (Invariant acquired by Snyk, `mcp-scan` is now a PyPI redirect stub, the successor `snyk-agent-scan` has zero mentions of proxy, guardrail or runtime and requires a Snyk account plus API egress of your skills and tool descriptions) [05]. Runtime goal-drift auditing: AlignmentCheck's honest cost is a 2.5 to 4 percent false-positive rate plus "significantly higher latency" on an answer path already at 11-25s, against zero drift findings in the ledger [05]. ML behavioural baselines: this project has produced **35 real agent serve turns in its entire life** (28 `serve:pm-agent`, 7 `serve:linear-scribe`, measured in `data/obs.db`), so a z-score is a coin flip [05]. The fourth, real-time budget metering, is already enforced: `src/resident.ts:406` passes `maxBudgetUsd` into every `query()` and the Agent SDK enforces it between model requests, which makes spec 7.4's "lagged enforcement" text stale for the per-task layer [05].

**Every collaboration recommendation in the wave failed its own entry test, so v0.5 adds no second collaborating agent and no channel adapter.** The multi-agent go/no-go gate needs 20 promoted eval cases; five exist [03]. Its recommended first build is a deterministic lint, which is a self-improving-loop artifact, not a multi-agent one [03][06]. The reviewer-agent experiment as designed needs roughly 240 human-adjudicated approval cards from an operator with a day job [03]. Slack past a draft-then-send path is gated on a Goodvest workspace admin who has not been asked three decisive questions [02]. The self-improving loop's judge calibration needs 30 to 50 hand labels but the corpus contains **one** human thumbs and **two** `needs_review` rows, and the negative class has size two, so a true-negative rate is not computable [06]. **The scarce resource in v0.5 is not compute, credentials or code: it is traces and one human's attention.** The ladder in section 10 therefore ends with a deliberate week of real use, because that week is what earns v0.6's decisions.

## 2. Remote reach: mostly a hardening dimension wearing a reach label

The reported pain was "cards expire while I am away from my desk". The diagnosis is two independent clocks plus a security regression [01].

**The clocks.** `src/bridge.ts:59` sets `timeoutMs = opts.timeoutMs ?? 10 * 60_000`; `src/resident.ts:388-394` narrows it to `Math.max(60_000, Math.min(10*60_000, reply_by - 30s))` so ten minutes is a hard ceiling in every path; `src/store.ts` sweeps a pending card past `expires_at` to `rejected` and emits `approval_expired`. A separate clock, `holdTtlS: 300` (`src/store.ts:126`), **drops** a gate-held message after five minutes, from the same console Inbox. Fixing only the approval clock leaves the shorter one running and the symptom recurs through the other door.

**The exposure.** MCP 2026-07-28's Streamable HTTP page makes Origin validation a **MUST** with a 403 response and localhost binding a **SHOULD**, citing DNS rebinding; RFA does neither. The SDK's content-type enforcement accidentally closes the trivial cross-origin POST (`text/plain` gets a 415) but rebinding survives, and under rebinding only `Host` still carries the attacker's hostname, so an allowlist must cover both headers. CVE-2025-49596 (MCP Inspector, CVSS 9.4, CWE-306 missing authentication, `UI:P`) is the archetype for a local dev listener with no auth [01].

**Reach options, decided.** Tailscale Serve documents that "only `http://127.0.0.1` is supported for proxies", so loopback binding and phone access are compatible, and it injects `Tailscale-User-Login`/`-User-Name`/`-User-Profile-Pic` while stripping those headers from inbound requests. Funnel is a hard reject: ports 443/8443/10000, non-configurable bandwidth limits, and verbatim "Funnel traffic, which is publicly available, does not include identity headers", which would publish a credential-less `/mcp`. ngrok free is 20,000 HTTP requests per month against a long-polling room with a random URL per restart. A VPS hosting the hub moves the Linear key, the Goodvest knowledge pack, the memory DBs and the hash chain onto a rented box. Cloudflare Tunnel plus Access is technically the strongest of the tunnels (outbound-only 7844, a verifiable RS256 `Cf-Access-Jwt-Assertion` against a published JWKS, a binding cookie against cookie theft) and is deferred, not rejected, with a clean trigger: the day a colleague needs access. Claude Code Remote Control is genuinely attractive (outbound HTTPS only, never opens inbound ports, auto-reconnect after sleep, a "Push when actions required" toggle, already paid for) and is kept as the fallback [01].

**Corrections the verifier forced, folded in.**

- The two-lost-cards incident is **not** in the repo's findings ledger. The only documented live approval succeeded (18 seconds). The code-level diagnosis stands entirely on its own, but the incident itself is operator report, not evidence, and the whole priority ordering of v0.5 was originally justified by it. Stated plainly here rather than laundered.
- **ntfy `http` action buttons carrying an `Authorization` header are rejected outright.** The notes proposed a per-card single-use bearer in the button; that credential sits in a broadcast message cached for 12 hours after delivery, protected only by a topic ACL, and any read-subscriber to the topic can approve the real card, producing a genuine Linear write stamped `origin:human`. It also violates rule 6 of the permission-relay contract the same notes adopt ("gate on sender identity, not room identity"): an ntfy action carries no sender identity at all. Push in v0.5 is **notification only**: a nag plus a link, no credential, no verdict path.
- **Tailscale identity headers as a second factor are rejected, not adapted.** With the hub on 127.0.0.1 behind `tailscale serve` and an ACL limited to Paul's own devices, an off-tailnet request cannot reach the hub at all, so the header adds nothing; on a single-user tailnet its value is a constant every device knows, and a constant is not a factor. The proposed mitigation (a second long-lived serve-only hop injecting a per-boot secret) is a new process and a new failure domain to defend a network whose entire membership is the operator. The upstream caution (denoland/clawpatrol#316) is real but its threat model is an operator who also fronts the port with nginx or cloudflared, which this design rejects elsewhere.
- **"Route auth events into the existing JCS-SHA256 hash chain" is not a line-count item.** `src/store.ts:408` seeds `room.chainHead = sha256hex(room.handle)` and every append uses `prev_hash: room.chainHead` on a room object: the chain is per-room by construction, and `/auth` is unauthenticated by definition, so appending one event per failed attempt hands an unauthenticated attacker unbounded growth in the audit trail being hardened. The right shape is a separate append-only auth log with its own genesis writing **aggregated counters per window**.
- **The Origin/Host allowlist must ship as configuration with the rejected value logged**, because whether `tailscale serve` forwards the original `Host` or rewrites it to the loopback target is unmeasured, and guessing wrong 403s the first tailnet request.
- Remote Control is a fallback with a stated cost the notes underplayed: approving through it means typing free text on a phone that a model interprets and then chooses to execute, which puts a language model in the provenance chain of an `origin:human` stamp. If it is ever used for approvals, the decide call must be a deterministic non-model command bound to a server-issued id, and the log must record both `channel=remote-control` and the fact that a model relayed the intent.
- Laptop sleep: `caffeinate` is dropped, not deferred. STATUS already records the sleep question as answered and handled (the supervisor detected the stale heartbeat, restarted pm-agent cleanly, and the nightly backup ran).
- Tailscale's Personal plan says verbatim "This is a free plan and is only suitable for non-commercial use of Tailscale". This is a personal tool used for Goodvest work. Settle it in writing and budget 8 USD per user per month as the fallback. It does not change the technical verdict.

**Unverifiable and load-bearing.** Whether `tailscale serve` passes the console's long-poll `room_listen` and stream without buffering, and whether an ntfy iOS action reaches a tailnet HTTPS URL from a locked phone. The first is a precondition for the reach rung; the second is moot now that push is notification-only. The MCP spec's own `X-Accel-Buffering: no` guidance is the first mitigation to try if buffering bites.

## 3. Channel adapters: everything past Stage 0 belongs to someone who has not been asked

Socket Mode settles the transport question on paper (one outbound WebSocket carries Events API and all interactivity payloads; Slack states there is "no need to verify or validate inbound events, because you're receiving the events over a pre-authenticated WebSocket"), and the internal-customer-built-app exemption is the load-bearing commercial fact: the 2025-05-29 changelog cuts `conversations.history`/`replies` to one request per minute with 15 objects for non-Marketplace apps, but "Internal customer-built applications are not impacted by these changes" and keep 50+ requests per minute at 1,000 objects [02].

The genuinely durable output of the dimension is a set of **non-decisions**: keep them, build nothing. The arXiv OpenClaw security analysis records, verbatim at the channel layer, that thirteen advisories share one root cause, developers keying allowlists on "human-readable sender fields, usernames, display names" rather than platform-assigned immutable identifiers, and that the pattern recurred across all 15 adapters, "suggesting the flaw was architectural rather than incidental". The prescription is one shared `resolveAllowlistIdentity()` "implemented once and audited once". RFA spec 12.1 already forbids authority from text; the adapter's job is to not reintroduce it: no slash command, no text path to approve, allowlist fails **closed** with no `*` default (the upstream fail-open bug wrapped its check in `if allowed_csv:`), unknown message subtypes dropped (`message_changed`, `message_deleted`, `thread_broadcast` bypassed sender authorization in a real advisory), channel topic and description never in a system prompt (a real CVE put exactly that in the model's system prompt), and reply only in the originating thread so an injected instruction cannot redirect output [02].

**Corrections the verifier forced, and they gut the build plan.**

- **The Stage 0 recommendation as written is unimplementable.** `slack_send_message_draft` belongs to a claude.ai-account-managed remote connector authenticated on Paul's own Slack user OAuth. `src/resident.ts:357-358` starts residents with `settingSources: []` and `mcpServers: { rfa, memory, linear }`, so no hub, supervisor or resident can call it; the only caller is a human-driven Claude session, which needs zero build and is not a channel adapter. Handing the hosted server to the Agent SDK instead requires confidential OAuth credentials from a directory-published or internal app, which is exactly the install Stage 0 claimed to bypass. It also errors with `draft_already_exists` at one pending draft per channel, and it attributes output to Paul, contradicting the same note's rule that agent output must not be indistinguishable from the human's.
- **The premise that Paul cannot install an app is unverified.** `Admin: No / Owner: No` was measured; the separate App Manager role is not surfaced by that profile read, and if "Require approved apps" is off, any member can self-serve `xoxb-` and `xapp-` tokens. The note assumed the answer that maximised its own finding, then reordered the entire build path on it.
- **Slack-clicker approvals are a strict security downgrade and must not ship.** Today `origin: "human"` comes only from `resolveOrigin(human_key)` and `role: supervisor` is refused without it, so approving requires possession of a provisioned key in a 0600 file on the laptop. Minting human-origin memberships for Slack clickers means the adapter process holds those human keys and its Slack-id lookup becomes the whole authority boundary: a phished Goodvest Slack account then approves agent writes to Linear. Worse, a per-human membership is only honest if each human has their own provisioned key; otherwise the audit record "approved by @alice" is fabricated attribution wearing better labels.
- **Socket Mode is the right transport for the wrong stated reason and hides the real failure.** RFA cannot receive webhooks behind NAT at all, so it could never have written the ten webhook-authentication bugs the note credits Socket Mode with preventing. And while the laptop sleeps the socket is down and Slack does **not** backfill: a mention is lost permanently, the `reactions.add` acknowledgement cannot fire because the event never arrived, and the v1 scope list omits `channels:history`, which is the only possible catch-up. That belongs in the design with a named mitigation, not in a footnote.
- **`linear-scribe` cannot be the second instance of a `ChannelAdapter` interface.** It is a resident with outbound in-process Linear GraphQL tools; Linear sends RFA nothing. A six-method interface with one implementation is the abstraction this project's ledger keeps punishing. Extract the one function the paper actually argues for (`resolvePrincipal`) plus one `dropRules()` predicate, and only from working code.
- **There is no redaction machinery to extend.** `src/obs.ts:237` `obs.prune(keepDays)` deletes rows; `grep -rn redact src/` returns nothing. Redacting an append-only hash-chained NDJSON is a whole-file rewrite plus a verifier that understands tombstones, which is a protocol change, not a sweeper flag.
- Two cheaper zero-admin outbound paths were missed entirely and are worth five minutes of checking inside Slack before any app conversation: a Workflow Builder webhook trigger and a channel email address, both member-creatable by default on paid plans, both giving the hub a plain HTTPS POST into a named channel with no bot token and no scope review.

**Verdict for v0.5: Slack ships as one email.** Send the Goodvest workspace admin three questions in one message (is "Require approved apps" on and who approves; is the workspace on Enterprise Grid; what is the message retention setting) plus the honest sentence the note buried: an AI tool on a laptop would read company Slack, forward content to Anthropic for inference, and keep a local copy that outlives your retention setting. Everything else waits for a written yes. Do note the demand side was never measured and the already-installed connector could settle it in twenty minutes: count mention-shaped requests over 30 days and count how often Paul pastes Slack content into `/ask-pm`.

## 4. Multi-agent: the right answer is "audit what you already run"

The dimension's own conclusion is correct and is the most valuable thing in it: **do not add a second agent to any RFA workflow until a deterministic lint has been tried and failed.** The cost multipliers are documented and consistent: Claude Code agent teams use "approximately 7x more tokens than standard sessions when teammates run in plan mode"; a controlled 100-scenario benchmark found multi-agent **lost** on accuracy (0.974 single vs 0.934 multi) at ~5.8x tokens and ~5.9x latency, with latency and token differences significant at p<0.001 while the accuracy difference was not; MAST found 41% to 86.7% failure rates across seven popular frameworks. The discriminator between a useful critic and theatre is external information, not agent count: Huang et al. show LLMs struggle to self-correct without external feedback and sometimes degrade, and the rover paper concludes multi-agent is "most justified when agents access distinct tools, data sources, or specialized capabilities". If the extra information is a checklist, the checklist is a lint [03].

The handoff design converged with everyone else on transferring the **task, not the transcript**: Anthropic's cross-session messaging says a message is "never conversation history or files" and agent-team teammates get the spawn prompt because "the lead's conversation history does not carry over"; LangGraph's supervisor defaults to `output_mode: "last_message"`; OpenAI still transfers history but spent 2026 shipping escape hatches (`input_filter`, `remove_all_tools`, and a beta `nest_handoff_history` that collapses the transcript into one bracketed message). A2A 1.0 contains **no** delegation or handoff mechanism, so there is nothing to be compatible with. The IETF audit-trail draft's `action_type: delegation` and its `prev_hash` rule (SHA-256 over RFC 8785 canonical JSON of the previous record) are byte-identical to what `src/jcs.ts` already computes, which is the strongest technical argument for making any future handoff an event in the room log rather than a peer-to-peer call: a direct call leaves a hole in the chain exactly where accountability matters [03].

**Corrections that kill the build plan for v0.5.**

- **"The receiver fetches referenced messages itself" has no read primitive.** `src/hub.ts` registers 12 tools and none fetch a message by id; `room_listen` is cursor-only. `artifact_refs: ["msg_..."]` is a dangling pointer whose only resolution is replaying the log from cursor 0, which is the full-transcript read the design forbids. The cheap fix the notes missed: reference **content-addressed local artifacts** (the scribe already writes dry-run drafts to `agents/linear-scribe/state/drafts/`), read with `Read`, no room-history access, no new verb.
- **The design contradicts itself on ownership**: one invariant moves ownership immediately, another parks the task in `handoff.pending_to` and has the receiver `claim` it. `claim` is atomic on a `submitted`, unowned, unblocked task, so a receiver cannot claim a `working` owned task; and `input_required` already has fixed semantics plus a 1:1 A2A mapping, so overloading it breaks both. The real cost is a new sub-state, a new accept verb, and edits to spec 10.2's state machine.
- **The hub cannot enforce the delegation rules the design assigns it.** `AgentCard` (`src/model.ts:22`) has no tool-scope field and tool enforcement lives in the resident's `allowedTools`, so a hub-checked `scope` subset is a self-declared audit annotation, not a capability restriction. `grep usd src/store.ts src/hub.ts` returns nothing: the hub has zero cost knowledge, so `budget_usd <= remaining per_task_usd` needs new cross-process coupling. Consequently the anti-laundering invariant reduces to prompt text, and Anthropic's own version is instruction plus a mode-specific classifier, not a capability block. Do not ship a control described as enforced when it is advisory.
- **A cheaper fourth arm dominates the reviewer-as-member experiment**: an Agent SDK **subagent** inside the scribe's own session gives distinct information, its own context and tool allowlist, its own model, and single-writer discipline at zero protocol cost. The wave tested the critic hypothesis in the most expensive possible harness. The same correction applies to breadth-first fan-out: it is served by subagents inside one resident, never by new memberships.
- **The state machine has a hole where it claims completeness**: nothing handles late acceptance or late completion after an ownership revert, which is duplicated work (MAST FM-1.3) created by the design. And the non-blocking rule, which is right, is priced at "a day" when it actually requires `src/resident.ts` to start a new turn on an old `conversation_id` from an out-of-band task event while holding the original asker's pending reply, which is a new resumption path plus a pending-reply store.
- `attributed_to` on runs is a one-valued column today (one human principal), so it answers no question; keep `spent_by` and defer the rest. A `handoff` conformance tier is ceremony with one implementation and one operator.

**The higher-yield version of this dimension, which nobody ran, and which v0.6 should:** RFA already runs a live multi-member system (pm-agent, linear-scribe, the `-hitl` sidekick, the supervisor, the console membership) and it produced four ledger bugs including identity theft via legacy state fallback and lease starvation during approval waits. Auditing the shipped collaboration's failure modes against MAST's 14 modes, using RFA's own log, has a higher expected yield than surveying whether to add a third agent. The one thing to keep from the handoff work now is the non-blocking rule as a spec sentence: **a handoff MUST NOT block the delegator's serve loop**, which is the generalization of two bugs already in the ledger and of `src/client.ts:278`'s existing `busy_loop` refusal.

## 5. Live knowledge: a copying problem, with a ranking problem underneath

pm-agent answers from 7 static files (48K, 6,642 words) while the handbook lists 46 pages, including none of `conformite/analyse-reglementaire` or `conformite/bonnes-pratiques` [04]. Webhook ingress is a clean reject for four of five sources on a sleeping laptop: Linear requires a "publicly accessible HTTPS, non-localhost URL", a 5000 ms response, and disables the webhook after 3 retries at 1 minute, 1 hour and 6 hours; Google Drive channels expire in 1 day (files) or 1 week (changes) with no auto-renew and carry no change detail; Confluence Cloud has no webhook UI at all. Watermark-driven catch-up is the correct shape, and a missed run costs only a bigger delta [04].

Search latency can be struck from the debate: measured locally on this laptop, FTS5 answers in 8.4 ms at 20,000 chunks and `sqlite-vec` brute-force KNN over 20,000 float[768] vectors in 2.67 ms, faster still with a metadata filter, so the famous "no stable ANN index" limitation is irrelevant at 100x this corpus. Cost is likewise not the argument: embedding the whole plausible corpus (roughly 550-800 chunks) is about half a cent. The honest reason to defer embeddings is dependency surface plus the absence of a measured retrieval failure, and `sqlite-vec` self-declares pre-v1 breaking changes with ANN still in an alpha line [04].

**Corrections the verifier forced.**

- **"One line" tokenizer fix is a silent no-op.** `src/memoryfs.ts:246` uses `CREATE VIRTUAL TABLE IF NOT EXISTS`, the live `facts_fts` DDL in `agents/pm-agent/state/memory.db` has no `tokenize=`, and FTS5 has no ALTER path for a tokenizer, so editing the source string changes nothing and `rebuild` rebuilds the old tokenizer. The real change is DROP, CREATE with the new tokenizer, rebuild, per agent DB, in a project with **zero** `ALTER TABLE` and no `user_version` anywhere in `src/`. The cheaper alternative missed entirely: `src/memoryfs.ts:279-298` already builds the MATCH string, so appending the FTS5 prefix operator (`"versement"*`) recovers `versements`/`arbitrages`/`autorises` with a one-character change, no DROP, no migration, and it also fixes the feminine-agreement case the Porter stemmer misses.
- **Binding the handbook MCP server to the pack is unimplementable and dangerous as scoped.** It is a claude.ai-account-managed remote connector on Paul's Claude login; `agentDefSchema` in `src/agentdef.ts` has **no** `mcp_servers` field (the spec's frontmatter example at line 59 is illustrative), and `src/resident.ts` hardcodes three servers with `settingSources: []`. The obvious shortcut, `settingSources: ['user']`, would inject all 28 connected connectors (Gmail, Drive, Slack, Supabase, Sentry, and the rest) into a haiku agent, assembling exactly the lethal trifecta the same note proposes to cut. **The right answer is in the handbook's own `tech/repos.md`: the handbook IS a git repo.** `git clone` plus one knowledge glob gives 100% of the 46 pages with no auth, offline capability, the unchanged Read/Grep path that already passes the parity gate, and per-file author, commit time and sha from `git log`, which is precisely the provenance the MCP does not expose. `git pull` in the existing nightly job replaces the whole invented `sources` table for the handbook class.
- **Linear read-through parameters do not exist on the endpoint the resident can call.** `list_documents(updatedAt, orderBy, cursor, fields)` is the claude.ai connector's MCP surface; the resident's available path is `src/resident.ts:227` POSTing to `https://api.linear.app/graphql` with `LINEAR_API_KEY`, where the query is `documents(filter: {updatedAt: {gt: ...}}, first:, after:)` and there is no `fields` parameter or `orderBy` enum. Separately, piping self-declared draft specs ("a figer au fil des validations", base rules negated by temporary rules, unresolved comments) into the agent that answers authoritative product questions is a correctness risk that nothing in the recommendation gates.
- **Do not set `valid_at` from a document's `updated_at`.** That is transaction time at the source, not when the fact became true in the world, and it mis-dates exactly the case bi-temporality exists for while corrupting the recency term in `retrieve()`. `observed_at` is the honest home for a source revision.
- **The 13-column `sources` table with a `body` column contradicts its own principle** ("mirror nothing, derive locally, cite upstream"): `UNIQUE(uri, content_sha256)` plus `body` stores every revision of every internal compliance document forever in an unencrypted SQLite file, and for the two sources actually in scope every column is either `git log` output or a single `updatedAt` validator. The watermark loop as written also has no tombstone path, so a retracted compliance page stays answerable forever.
- **The reranking evidence does not license "add a reranker, not embeddings".** The cited table has no BM25-plus-rerank row: the +17.2pp MRR@3 is measured hybrid to hybrid-plus-rerank, i.e. on top of the dense embeddings the recommendation claims to precede, and the reranker is a paid SaaS endpoint. The cheapest real gain in the same table was never mentioned: contextual chunk enrichment (0.717/0.454 vs 0.695/0.433), which is a preprocessing prompt with no new model and no vector store.
- The `retire-agent` runbook and the fact-revalidation sweep both target zero rows today (all 7 live facts are `source_origin='agent'`; there is no human-origin fact and no `human_owned` source tier). Keep the answer-side behaviour ("these two sources disagree, a human must arbitrate", which pm-agent already produced unprompted and Paul valued); drop the sweep until a fact exists that it could fire on.
- Notion and Confluence connectors **are** provisioned on the account in a needs-authentication state, so the defer verdict is right but "no connector present" was wrong.

**The defect that survives every lexical fix, reproduced on real text:** "Quel est le ticket d'entree le plus bas ?" never retrieves the chunks that say "Montant minimum : 100 EUR / 300 EUR", because `offre/scpi.md` says "Ticket d'entree minimum" while the Linear doc says "Montant minimum" for the same concept. Cross-source vocabulary drift is the structural reason a multi-source corpus eventually needs semantics, and it is already present. That is the embeddings trigger, and it is a measurement, not an opinion.

## 6. Governance v2 and the self-improving loop: reject the ceremony, fix the meters

**Rejected with reasons, and the reasons are strong** [05][06]: the flow-rule DSL and proxy (runtime half not in open source; `snyk-agent-scan` requires a Snyk account and ships your skills and tool descriptions to their API, which for `agents/pm-agent/knowledge/**` means sending an employer's confidential product documentation to a third-party security vendor unapproved); AlignmentCheck as a runtime gate (2.5-4% FPR, documented "significantly higher latency", a capable model call after every action, `TOGETHER_API_KEY` in the reference implementation, zero drift findings in the ledger); ML anomaly detection (35 lifetime serve turns); Nautilus Compass persona drift (ROC AUC 0.83 with no published false-positive rate, plus an embedding dependency spec 5.1 deliberately avoided); Cedar v4.12.0 and OPA v1.19.1 (healthy, unchanged in relevance, a second runtime for a three-field match `deploy/gate.json` already solves); per-token cost interrupts (Anthropic's own hosted platform enforces "between model requests, not mid-request" and bounds overshoot at one request per thread); DSPy/GEPA/MIPROv2/TextGrad; SEAL, Voyager, PoLL; the IETF audit-trail export (revision -00, individual submission, no working group, expires 2026-09-29, and RFA's chain already matches its algorithm); EU AI Act and NIST work items (the Digital Omnibus, in force 2026-07-27, deferred standalone high-risk to 2027-12-02 and product-embedded to 2028-08-02; Article 50 targets public-facing chatbots and synthetic media; NIST's COSAiS overlays are unpublished).

**Corrections that matter for what does get built.**

- The GEPA reject must **not** be grounded on the dollar figure. `auto_budget()` scales `max_metric_calls` with valset size, so the tutorial's 1,643 metric calls belong to a 132-example corpus; at 5 to 20 cases it is roughly 60 to 250 calls, minutes and single dollars. The reject stands on the arguments that survive: no adapter (RFA's optimizable unit is `agent.md` frontmatter plus body plus knowledge globs plus tool allow/deny plus room bindings, not a DSPy `Signature`), the no-framework constraint, DSPy's own minibatch default of 35 exceeding the whole corpus, and the verbatim discovery limitation that an optimizer "can refine a prompt to perform better on known failures, but it cannot discover new ones" against two lifetime known failures.
- **`taskBudget` is unusable here.** The docs say "Task budgets are not supported on Claude Code or Cowork surfaces" and list Sonnet 5 and Haiku 4.5 as not supported, which is both of RFA's models and its only runtime. There are also no scheduled runs to put it on: neither live pack declares `schedules:`, the engine `schedules` table has 0 rows, and all 46 engine runs are `kind=serve`. The "weekday morning digest" exists only as a code fence in the spec.
- **Subagent caps are unreachable today, so ship the guard where the risk arrives.** Neither pack allows `Agent` or `Task`, and `canUseTool` default-denies, so no resident can spawn one subagent. The durable control is a validation assertion in `src/agentdef.ts` that a pack cannot declare `Agent`/`Task` without explicit opt-in.
- **The budget fix is three edits, not one.** The `subtype !== 'success'` guard at `src/resident.ts:419` **throws**, so `spend.usd += costUsd` at line 429 is never reached and the catch-path `obs.record` omits `cost_usd` entirely (NULL, not $0). Hoisting the read is necessary but insufficient: also return the spec'd `overloaded` refusal instead of throwing for `error_max_budget_usd`/`error_max_turns`, and add `cost_usd` to the error-path record. And `min(per_task_usd, per_day_usd - spend.usd)` needs a **viability floor**, not a `> 0` check: because the cap is enforced between requests, a $0.02 remainder burns a real request per question and returns a truncated refusal instead of the clean "daily budget exhausted" line 347 already gives. Frame the whole thing as pre-failure hygiene: across 433 spans, zero runs have ever hit a ceiling and lifetime spend is $2.65 against $3 and $5 day caps.
- **The watchdog invariants are regression monitors, and one of them false-fires by construction.** Three of the six watch bugs already fixed with regression tests. Invariant 1 as stated ("present-but-lease-expired observers > 0") contradicts the shipped 24h `observerPruneMs` sweep and would fire on every clean supervisor restart after laptop sleep; it must read "expired for longer than `observerPruneMs`". The one anomaly present in live state right now was not in the proposed set: `data/runs.db` has 3 of 10 `linear-scribe` engine runs stuck in `running`. Replay against two weeks of `data/rooms/*.ndjson` plus `data/obs.db` is a gate, not a formality: any invariant that false-fires does not ship.
- **The judge critique is right and its calibration is blocked on data.** `src/evals/judge.ts` uses `CHOICES = [0, 0.25, 0.5, 0.75, 1]`, a Likert in disguise, with a `RUBRIC` string constant written before any failure data existed, unvalidated against any human label. Binary, a versioned `evals/rubric.md` with `rubric_hash` on every feedback row, few-shot anchoring, and cross-tier judging (the call site is `claudeJudge(ROOT, ...)` with no opts) are all cheap and correct. But TPR/TNR needs a negative class and the negative class has **two** members, so "label 30-50 traces this week" would exhaust the 35-trace lifetime corpus and still not compute a rate. Re-scope to: label every trace as it arrives, revisit calibration at 10 confirmed failures.
- **The assembled-context viewer needs persistence the system does not have.** `SDKControlGetContextUsageResponse` in the installed `.d.ts` DOES itemize (categories, memoryFiles, mcpTools with token counts), so the stated SDK constraint was wrong in the recommendation's favour. The real hole: `obs.record` stores only 300-char input/output slices, and the top-5 retrieved facts plus compiled blocks are rebuilt fresh per turn, so a viewer over a past run can only re-assemble **today's** context. Either add a per-run snapshot or scope the viewer to live runs and say so.
- **The review lane defers to a digest.** Measured today: queue 1 (`feedback.score<=0 OR needs_review`) yields **2 rows in project history**; queue 2 (judge vs computed disagreement) yields 0 and structurally cannot yield more (4 judge rows, all 1.0). Queue 3 is not even expressible over `obs.db`: there is no capability column, no agent-side tool-name column (only hub spans land as `rfa.<tool>`), and gate outcomes are room-log system events, of which only `policy_refused` surfaces indirectly. Ship the counts into `#ops`; build the console lane when the queues are non-empty three weeks running.
- **The reflective diff proposal inherits a security requirement nobody stated.** Its input is failing trajectories carrying untrusted peer content and its output is a proposed diff to the system prompt, with "a human applies it" as the only barrier. That is the worm channel spec 14.3 exists to close, and the threat is live in this repo (injection marker to `gate_alert`, private-key material to `policy_refused`). `src/consolidate.ts` already solved this shape: boundary-wrap the content **and** rebuild the MemoryGate window from the very batch. Any future reflector must do both, and must also run `MemoryGate.inspectText` over the **proposal**. The ACE id-and-counter format additionally presupposes an id-carrying bullet store, so adopting it first requires restructuring `agent.md`, which rotates the definition hash and must clear the parity gate.
- The 100%-pass baseline is real and the gate's defect is not the one the note fixes: it compares `r.score` against a stored point estimate of `1` at `trials: 1` with ~5% flake, so a no-change run already false-regresses roughly 19% of the time, and raising to `trials>=4` against a hard `1.0` makes that **worse**. Gate on pass^k with an explicit tolerance band, or store a distribution.

**What survives and is worth building:** the meters (budget floor, cost on error paths, the `overloaded` refusal, the `Agent`/`Task` validation guard), the missing account layer, a `retire-agent` **script** rather than a checklist (the ledger's own failure mode is that under time pressure step 1 happens and nothing else does), the binary judge with a versioned rubric, `case.yaml` provenance fields (`CaseDef` is a plain `YAML.parse` with no zod, so unknown keys are free), and the anti-ossification discipline of treating 100% as a warning.

## 7. Synthesis: the RFA v0.5 design

The theme is **trust it away from the desk**. Nine decisions, each traced to a measured defect, each inside Paul's control with no third-party dependency. Markers as in wave 02: **ADOPT** (verbatim shape from evidence), **ADAPT** (shape kept, implementation changed), **BUILD** (new but small), **REJECT**.

### 7.1 Exposure: reduce before adding clients

**BUILD [01]:** `src/main.ts:326` becomes `server.listen(port, host, cb)` with `host` defaulting to `127.0.0.1` and overridable by `--host`. An `Origin` **and** `Host` allowlist returning 403, shipped as configuration (`--allow-host`, repeatable) with every rejected value logged, because whether `tailscale serve` forwards the original `Host` is unmeasured. `authed(req)` moves ahead of `GET /api/agents`, `/api/agents/<n>/definition`, `/api/runs`, `/api/summary`, `/api/approvals`; the console's read path and the project-local MCP registration at `http://localhost:8790/mcp` both need updating in the same commit or they break. Constant-time compare on `human_key` with a per-IP attempt limit and lockout. Auth events go to a **separate** append-only log with its own genesis writing aggregated counters per window, never into a room's chain.

### 7.2 The card clock: one semantics, and it is not "reject"

**BUILD [01][03]:** three clocks become one vocabulary.

- `src/store.ts` gains a distinct resolution `expired` alongside `approved`/`rejected`. Expiry still fails closed, the asker still gets a refusal, but the refusal reason is `deadline_expired`, so the hash-chained log stops recording a clock as a considered human "no". This is the smallest change with the largest provenance payoff, and it is spec 0.1.8 wire text (`allowed_decisions` gains no member; the resolution enum does).
- The 10-minute ceiling in `src/resident.ts:391` is deleted. The human window becomes the asker's window: `min(reply_by - 30s)` with no upper cap, and `npm run ask` defaults `reply_by` to 30 minutes instead of 600s. This is what actually buys "I stepped away", and it is honest about its limit: the run is still a live Agent SDK query holding a lease, a sidekick and a budget window, so the ceiling is however long that survives, not 24 hours.
- `holdTtlS` rises from 300s to the same window and a held message that expires is logged and **surfaced** in the console Inbox as expired rather than silently dropped. Fixing only the approval clock leaves the shorter one running.

**REJECT for v0.5: parking (persist the tool-call intent, end the run, re-materialise on approval).** It is not a TTL change plus a status enum. `requestApproval` is an in-process `while (Date.now() < deadline)` loop inside `canUseTool` inside the serve handler: the pending decision exists only as a stack frame and a live sidekick cursor, nothing is persisted, and the engine memoizes per `(run, step id)` where the whole serve turn is one run and the Linear write is not a step, so a replay returns the journaled turn result and never re-executes the write. A 12-24h window is also guaranteed to cross a restart (STATUS records five scribe restarts in one day). Real parking needs durable storage of the card plus the merged input, an immediate deferred return from `canUseTool`, a `deferred` disposition in the protocol with defined `reply_by` semantics, and a fresh tool-only execution path with no model in the loop. That is the wave's largest hidden cost and it is unbudgeted. Trigger to unpark in section 8.

### 7.3 Reach: one thin slice, both directions

**ADOPT [01]:** Tailscale on the Mac and the iPhone; `tailscale serve --bg --https=443 http://127.0.0.1:8790`; a tailnet ACL limited to Paul's own devices; MagicDNS name plus the tailnet HTTPS cert. This is the only surveyed option that obeys the MCP localhost SHOULD and still reaches a phone. **The console is the sole verdict surface.**

**ADAPT [01]:** push is **notification only**. A card appearing publishes a message with a title, the tool name, a five-letter alias and a link to `https://<node>.<tailnet>.ts.net/console#<room>`. No credential in the payload, no action button, no verdict path. A second confirmation message is published when the card resolves, because a notification tap gives no visual feedback and the operator otherwise cannot tell.

**BUILD [demand side, unowned by any dimension]:** a five-second capture path, because the flywheel's actual constraint is that 35 serve turns exist. `POST /api/ask {room, question, reply_by}` behind the session token, plus an Apple Shortcut and a Raycast script that call it, so a question can be asked from the phone or from a hotkey without a terminal. This is the cheapest lever on every other loop in the wave and it was the wave's structural hole.

**REJECT [01]:** Funnel, ngrok, a VPS hosting the hub, hand-rolled WireGuard, email action links (a one-tap approve is a side effect on a safe method delivered into a mailbox with scanners and prefetchers, and the POST-confirm fix destroys the one-tap property), a PWA with Web Push, Tailscale identity headers as a second factor, `caffeinate`. **DEFER:** Cloudflare Tunnel plus Access (trigger: a colleague needs access; copy the `Cf-Access-Jwt-Assertion` claim shape if RFA ever needs a real remote identity assertion), Claude Code Remote Control as the documented fallback (`claude --rc`, `/config` push for actions required), keeping `ssh -N -R ... -o ExitOnForwardFailure=yes` as break-glass.

### 7.4 Credentials: three tiers, stated once

| Principal | Credential | Lifetime | Notes |
|---|---|---|---|
| Human at the console | `human_key` presented once, hub mints a session token | short, sliding, plus a new **absolute** cap and `POST /auth/revoke` with a persisted `revoked_before` | rotate on first auth and on each `approvals/decide`; reject IP pinning (roaming laptop and phone) |
| Agent at `/mcp` | one static bearer per principal in `data/secrets.json`, checked before the MCP handler dispatches | long, rotated by hand | Claude Code's documented static `headers` with `${ENV_VAR}` expansion is enough; `headersHelper` "executes arbitrary shell commands" and is unnecessary until rotation is automatic |
| Push action | **none.** A link only | n/a | a bearer in a broadcast push payload is a standing grant to the workbench for any topic reader |

**ADOPT [01] as a spec edit, because the current text is unsatisfiable:** re-label the platform spec's "T1 OAuth" honestly as **shared-secret transport authentication that is explicitly NOT MCP authorization**, and reserve `401`/`WWW-Authenticate`/audience-validation vocabulary for T2. MCP 2026-07-28 makes authorization OPTIONAL, requires RFC 9728 protected resource metadata as a server MUST when authorization IS supported, and **deprecates Dynamic Client Registration** in favour of Client ID Metadata Documents. Keycloak's own MCP page says verbatim "Keycloak cannot recognize `resource` parameter". A hub that emits `WWW-Authenticate: Bearer` while serving no `/.well-known/oauth-protected-resource` advertises a posture it does not have. Demote the RFC 8693 token-exchange mention to T2/T3 rather than deleting it: the same spec's "MUST NOT pass through the token it received from the MCP client" is exactly the on-behalf-of problem the hub has when calling Linear.

### 7.5 Knowledge: clone it, provenance it, pin it for evals

**ADAPT [04]:** the handbook joins the pack as a **git clone**, not an MCP binding: `git clone` the handbook repo to a gitignored path, one knowledge glob in `agents/pm-agent/agent.md` (out-of-pack globs already work), `git pull` in the existing nightly supervisor duty. 46 pages, no auth, offline, unchanged Read/Grep path, and per-file author plus commit time plus sha from `git log` as free provenance.

**BUILD [04]:** three provenance columns on `facts` (`source_uri`, `source_author`, `observed_at`) plus `revalidate_after`, added behind the project's **first** migration mechanism (`user_version` in `src/memoryfs.ts`, because there is no `ALTER TABLE` anywhere in `src/` and each agent has its own DB). `valid_at` stays NULL unless the text states a date: setting it from a document's `updated_at` mis-dates exactly the case bi-temporality exists for. No `sources` table with a `body` column, and no verbatim mirror of internal compliance documents.

**ADAPT [04]:** retrieval gets the FTS5 **prefix operator** in the existing MATCH builder (`"versement"*`), which is one character and fixes four of six measured French morphology misses including the feminine-agreement case Porter misses. The tokenizer swap (DROP, CREATE with `porter unicode61 remove_diacritics 2`, rebuild) is a second, separately-verified step behind the migration mechanism, not "one line".

**BUILD [04][06], and this resolves the read-through-versus-determinism contradiction:** the eval and parity paths read a **pinned dated snapshot** (a recorded git sha for the handbook, a recorded corpus version in `evals/baseline.json`), while live answers read the working clone. Otherwise an upstream handbook edit becomes an `exit 1` regression that is not one, and the SCPI contradiction, which is live upstream and will change when its owner fixes it, silently breaks the gate.

**ADAPT [04]:** the answer-side conflict behaviour is what ships, not the sweep: when two sources disagree, say so and name both, which pm-agent already did unprompted and Paul valued. The deterministic detector (disjoint numeric values under headers matching `/ticket|montant\s+min|minimum/i` within one document, plus a marker regex for `temporaire|derogation|a figer|au lancement`) is two regexes fitted to two examples; validating it over all 46 pages plus 30 Linear documents is a gate on adopting it at all, not a fallback tweak.

**REJECT [04]:** embeddings, ANN, HyDE (worst strategy in the cited benchmark, and this corpus is numbers), a reranker as the first addition (the evidence measures it on top of dense retrieval using a paid SaaS endpoint), webhook receivers, graph or vector platforms, PROV-O, LLM-judge contradiction detection over the corpus, Notion and Confluence. **DEFER:** `search_result` content blocks behind a one-hour spike, contextual chunk enrichment as the cheapest untested gain.

### 7.6 Meters and the account layer

**BUILD [05]:** in `src/resident.ts`, `maxBudgetUsd = min(per_task_usd, per_day_usd - spend.usd)` with a **viability floor** (refuse at pickup when the remainder is below a realistic per-run cost, so a near-zero window does not burn a request per question); hoist the `total_cost_usd` read above the `subtype` guard at line 419; return the spec'd `overloaded` refusal with `spend=X budget=Y` for `error_max_budget_usd`/`error_max_turns` instead of `Error("brain error")`; add `cost_usd` to the error-path `obs.record`; and fold `src/consolidate.ts`'s own spend into the same ledger, which today hides about 3% of pm-agent's day. Correct spec 7.4's "lagged enforcement" text for the per-task layer, which the SDK already enforces between model requests.

**BUILD [05], the layer no dimension noticed was missing:** spec 7.4 layer 3 has no implementation. A supervisor-global cap on Claude turns in flight across all residents and background passes, with the spec's own priority order (pending approvals and human-facing serves first, scheduled jobs next, consolidation and evals and judges last), plus an account-wide pickup pause on a provider rate-limit error. This is the arbiter for the resource that is actually binding, the one subscription window shared with Paul's own interactive sessions, and **it must exist before any new background loop.** v0.5 admits at most **one** new scheduled job (the `#ops` queue digest); the reflective diff pass, the goal-adherence lint, the fact-revalidation sweep, the launchd catch-up sync and the Socket Mode process are all out.

**BUILD [05]:** a `retire-agent <name>` **script**, not a runbook checklist, because the ledger's own failure mode is that step 1 happens under time pressure and nothing else does: stop via the supervisor command channel, leave rooms plus sidekick, `room_admin evict` remnants, archive `state/memory.db` to `~/Backups/rfa-agent-com/retired/`, keep feedback-bearing `obs.db` rows, `git rm agents/<name>/agent.md` so the digest vanishes from every roster. Note step 4 (dropping secret names) is hygiene not control: the supervisor injects only names the definition declares, so removing the definition already ends injection.

**BUILD [05]:** an assertion in `src/agentdef.ts` that a pack cannot declare `Agent` or `Task` in `tools.allow` without an explicit opt-in field, which closes subagent fan-out at the layer where the risk would actually arrive.

### 7.7 Instruments: make the judge and the gate mean something

**ADAPT [06]:** binary judge instead of `CHOICES=[0,0.25,0.5,0.75,1]`; `RUBRIC` moves out of `src/evals/judge.ts` into a versioned `evals/rubric.md` with `rubric_hash` recorded on every judge feedback row; two or three few-shot critiques from Paul's own labels; the runner's `claudeJudge(ROOT, ...)` call site passes a **different model tier** than the subject, because self-preference is causally demonstrated and cross-tier judging is the only mitigation available under one Claude subscription. The judge may set `needs_review` and never gate: today it cannot gate anyway (the runner computes regressions from `r.score` alone), so state this as adding a write path, not removing an authority.

**ADOPT [06]:** provenance fields on `case.yaml` (`origin_run_id`, `origin_room`, `origin_seq_range`, `promoted_at`, `failure_mode`), stamped by `scripts/promote-case.ts`. These are free (`CaseDef` is an unvalidated `YAML.parse`, so unknown keys pass). `tier` and `last_failed_at` are **not** free (they need runner mutation of gitignored pack-local case files and tier filtering in `discoverCases()`), so they wait.

**BUILD [06]:** the eval gate stops comparing `r.score` against a stored `1` at `trials: 1`. Either gate on pass^k with an explicit tolerance band or store the baseline as a distribution, and record the per-case definition hash (the case set spans two definitions plus a replay case with none) and the corpus version. Print the measured flake rate next to any verdict.

**ADAPT [05][06]:** the `#ops` digest, not a console lane. Two SQL queries over `obs.db` (`feedback.score<=0 OR needs_review`; cost or latency above p90) posted into the existing `#ops` room on the existing supervisor tick. Queue 3 as specified is not expressible over `obs.db` and needs new instrumentation; say so rather than pretending it is a third `SELECT`. Watchdog invariants ship **only** after replay against two weeks of `data/rooms/*.ndjson` plus `data/obs.db` fires on the known incidents and nothing else, with invariant 1 corrected to "expired for longer than `observerPruneMs`", and with the one live anomaly (`data/runs.db`: 3 of 10 scribe runs stuck in `running`) added to the set.

**BUILD [attention economics, the scarce resource]:** **one** labelling artifact serves three dimensions. In one sitting, over the same traces: a binary pass/fail label (7.7), a gold source URI (the retrieval question), and promotion with provenance fields. Four separate labelling campaigns priced at zero is the wave's most expensive unpriced assumption.

### 7.8 The invariants that survive as spec text and cost nothing

- **A handoff MUST NOT block the delegator's serve loop** [03]. The generalization of ledger bugs 4 and 6 and of `src/client.ts:278`'s `busy_loop`.
- **Reserved name prefixes.** `room_join` performs no name validation at all, so nothing today stops an agent joining as `human:...` or `console...`. A 20-line guard plus a test, worth doing on its own merits. Related and latent: `consoleMembership()`'s `startsWith("console")` first-match lookup misattributes the moment a second hub-minted human membership exists.
- **Authority never comes from text** [02]. Already spec 12.1; restate it as the rule any future adapter inherits, alongside "allowlists fail closed" and "unknown message subtypes are dropped".
- **Never fetch a URI discovered inside another document's body** [04]. The live "Regles metiers" document carries five Drive links plus two external ones. Strip all tags and keep inner text rather than blocklisting named tags, because a named-tag blocklist is the 95%-catch filter this project's own sources call a failing grade.
- **Any future reflector over failing traces boundary-wraps its input, rebuilds the MemoryGate window from the batch, and runs `MemoryGate.inspectText` over its own proposal** [06]. Otherwise it is the worm channel spec 14.3 exists to close.
- **Local-first, amended honestly** rather than eroded quietly: no third party holds durable Goodvest content; transient notification metadata (a title, a tool name, an alias, a link) may cross **one** named boundary. Tailscale coordination and a push service fit; Telegram card previews, Slack ingest of colleagues' content, and Snyk-bound skill and knowledge scanning do not.

### 7.9 The two decisions that flip three dimensions at once

**Does v0.5 admit a second human principal? No.** Wave 02 deferred it; admitting it fires the flow-rule taint trigger, the multi-agent chained-token reversal, and a compliance question nobody has asked. The park is what keeps those rejections valid.

**Does v0.5 ingest another human's content? No.** 05's rejection of flow and taint rules is explicitly conditional on "no auto-approved external side-effecting tool and no second human's content in a room". Slack ingest is colleagues' content and read-through puts untrusted external documents in the answer path. **Drop the ingest, keep the rejection.** If a future release ships either, it also ships the ~50-line run-scoped taint set on the existing engine `steps` table plus PreToolUse/PostToolUse hooks. Do not ship the ingest while citing the rejection.

## 9. Spikes: the cheap experiments that settle what is left open

1. **30 min, settles the whole reach rung.** `server.listen(port, "127.0.0.1")` then `tailscale serve --bg --https=443 http://127.0.0.1:8790`; open `https://<node>.<tailnet>.ts.net/console#r_9a25e48c0e` on the iPhone; watch a live room and click one intervention. **Proves:** whether the Serve proxy carries the console's long-poll `room_listen` and stream without buffering. If it buffers, try `X-Accel-Buffering: no` before redesigning anything.
2. **1 h, settles L0 compatibility.** Add the Origin/Host allowlist and flip reads to require the token, then run `npm test` (85), `npm run e2e`, `e2e:full`, `npx tsx dogfood/parity.ts`, plus one real Claude Code `/mcp` connect over the tailnet hostname and one console load. **Proves:** whether the allowlist 403s a real client, and which `Host` value `tailscale serve` actually forwards.
3. **30 min, the highest-value half hour in the list.** Run `npm run evals` five times with no code changes and count how often the baseline diff exits 1. **Proves:** the gate's false-positive rate. If it trips at all, raise trials and add a tolerance band before adding a single case.
4. **1 h.** Run the two expressible review queues against today's `obs.db` and count results per week. **Proves:** whether the flywheel's input exists. Today's answer is 2 rows in project history, so expect this to confirm the digest-not-lane decision.
5. **1 h, the demand-side experiment nobody ran.** Wire `POST /api/ask` plus an Apple Shortcut, then use it for a week from the phone and count questions asked that would not otherwise have been. **Proves:** whether capture friction, not reach, is what has kept the corpus at 35 turns.
6. **2 h.** `git clone` the handbook, add the glob, run the parity gate and compare `total_cost_usd`, `num_turns` and wall time against the 7-file baseline on the existing fixtures. **Proves:** whether 46 pages of context (including 22 pages of regulated compliance analysis) helps or hurts a haiku agent with `max_turns: 8`. If it hurts, the answer is per-file retrieval hints over the clone, not fewer pages.
7. **1 h.** Add the prefix operator to the MATCH builder in `src/memoryfs.ts` and replay the ~40 real French questions extractable from the 72 pm-agent episodes, diffing top-5 sets. **Proves:** whether the measured morphology gain is real on live data or a synthetic-corpus artifact masked by the forgiving OR-of-terms query.
8. **2 h, settles the watchdog recommendation entirely.** A scratchpad `.mts` script computing the candidate invariants over two weeks of `data/rooms/*.ndjson` and `data/obs.db`. **Proves:** which invariants fire on the known incidents and nothing else. Any that false-fire do not ship. Include the live `running`-forever engine runs.
9. **1 h, cheap and decisive on the card clock.** Set the ask's `reply_by` to 30 minutes, let a card sit 25 minutes with the laptop awake, then approve. **Proves:** whether the run survives that long (lease renewal, sidekick, session, budget) or whether parking is required sooner than the ladder assumes.
10. **1 h.** Set `per_task_usd: 0.01` on a scratch pack and drive one question. **Proves:** the `overloaded` refusal path, a nonzero `cost_usd` row in `obs.db` for a capped run, and no generic `brain error`.
11. **1 h, highest-risk unknown in the whole wave.** Set `per_task_usd` just above the cost of reaching `save_document`, then sit on the approval card until the budget stop fires. **Proves:** what happens to the card, the asker and the `-hitl` sidekick when a budget stop lands mid-approval. This is the exact interaction that produced two live bugs already. Anthropic's own hosted platform says "a pending ask outranks the cap", which is the target behaviour to copy.
12. **20 min, zero Goodvest involvement.** Count mention-shaped requests over 30 days with the already-installed Slack connector, and check inside Slack whether members may create Workflow Builder webhook triggers or channel email addresses. **Proves:** whether Slack deserves any v0.6 budget, and whether a zero-admin outbound path already exists.

## 10. The v0.5 ladder

Five rungs, each independently shippable and live-verifiable in days, each behind the existing gates (`npm test`, `npm run e2e`, `npx tsx dogfood/parity.ts`, live wire verification against the standing room, findings appended to STATUS.md). Ordered so rung 0 relieves the sharpest pain.

### v0.5.0: cards stop dying on a clock, and the hub stops being on the LAN

**Delivers.** `src/main.ts` binds `127.0.0.1` by default with a `--host` override; a configurable `Origin` and `Host` allowlist returning 403 with rejected values logged; `authed()` ahead of all four `GET /api/*` read routes (console read path and the project-local `http://localhost:8790/mcp` registration updated in the same commit); constant-time `human_key` compare with attempt limiting; a separate append-only auth log writing aggregated per-window counters. Then the clocks: a distinct `expired` resolution in `src/store.ts` with refusal reason `deadline_expired`; the 10-minute ceiling in `src/resident.ts:391` deleted so the window is the asker's; `npm run ask` defaults `reply_by` to 30 minutes; `holdTtlS` raised to the same window with expiry surfaced in the Inbox instead of dropped. Plus two free invariants: reserved name prefixes in `room_join`, and the exact-name fix to `consoleMembership()`.

**Proves it works on the live wire.** From a second device on the same Wi-Fi, `curl http://<laptop-ip>:8790/api/approvals` connects to nothing. A hostile `Origin` on `POST /mcp` returns 403. A tokenless `GET /api/agents/pm-agent/definition` returns 401. `npm run ask` a scribe draft, walk away 25 minutes, approve in the console, and the Linear write completes. Let a second card lapse and confirm the log shows `approval_expired` with resolution `expired`, and the asker's refusal reads `deadline_expired`, not a human "no". All 85 tests, both e2e suites and the parity gate stay green.

**Does not include.** Parking. Any push. Any tunnel. Any new credential tier. Multi-hour or multi-day card windows.

### v0.5.1: reach, both directions

**Delivers.** Tailscale on the Mac and the iPhone; `tailscale serve --bg --https=443 http://127.0.0.1:8790`; ACL limited to Paul's own devices; MagicDNS name in the `Host` allowlist. Notification-only push on card creation and card resolution: title, tool name, five-letter alias, console deep link, **no credential and no action button**. `POST /api/ask` behind the session token plus an Apple Shortcut and a Raycast script, so a question takes five seconds from anywhere.

**Proves it works on the live wire.** Approve a real card from the iPhone over the tailnet URL, with the console as the only verdict surface, and confirm the room log records a human-origin intervention. Ask a question from the Shortcut with the laptop lid closed on AC and get an answer. Confirm the console's long-poll stream survives the Serve proxy (spike 1); if it buffers, that is the finding and the rung ships without the live stream.

**Does not include.** Verdict-by-push. Telegram. A PWA. Funnel or any public endpoint. Identity headers as a factor. Remote Control as anything but a documented fallback.

### v0.5.2: honest meters and the account layer

**Delivers.** `maxBudgetUsd = min(per_task_usd, per_day_usd - spend.usd)` with a viability floor; the cost read hoisted above the `subtype` guard; `overloaded` refusals carrying `spend=X budget=Y` for `error_max_budget_usd` and `error_max_turns`; `cost_usd` on the error-path `obs.record`; `src/consolidate.ts` spend folded into the same ledger. Spec 7.4 layer 3 implemented: a supervisor-global in-flight cap with the spec's priority order and an account-wide pickup pause on a provider rate-limit. The `Agent`/`Task` opt-in assertion in `src/agentdef.ts`. A `retire-agent <name>` script. Spec 7.4's "lagged enforcement" text corrected for the per-task layer, and the T1 relabel of 7.4 landed as spec prose.

**Proves it works on the live wire.** Spike 10 (a $0.01 cap yields an `overloaded` refusal and a nonzero cost row). Spike 11 (a budget stop mid-approval, which is the highest-risk unknown in the wave). Set the global cap to 1 and confirm a scheduled consolidation pass yields to a human-facing serve rather than racing it. Run `retire-agent` on a throwaway pack and confirm the roster shows no remnant and no orphaned sidekick.

**Does not include.** Any new scheduled job. Watchdog invariants (they wait on spike 8). Anomaly detection. `taskBudget`. Per-token metering.

### v0.5.3: knowledge that covers the corpus and cites its source

**Delivers.** The handbook as a git clone with one knowledge glob and `git pull` in the nightly duty; per-file provenance from `git log`. The project's first migration mechanism (`user_version` in `src/memoryfs.ts`) carrying three provenance columns plus `revalidate_after` on `facts`, with `valid_at` left NULL unless the text states a date. The FTS5 prefix operator in the MATCH builder. A pinned handbook sha plus a corpus version recorded in `evals/baseline.json`, so the eval and parity paths read a snapshot while live answers read the clone. Answer-side conflict behaviour stated in the pack prompt: name both sources and ask for arbitration.

**Proves it works on the live wire.** Ask a question whose answer lives only in `conformite/analyse-reglementaire`, which the 7-file pack cannot answer today, and get a cited answer. Ask the SCPI ticket question and get both numbers plus an explicit "these disagree". Run the parity gate before and after an upstream handbook edit and confirm it does **not** false-regress. Confirm one new fact carries `source_uri` and `source_author` from `git log`.

**Does not include.** Embeddings, ANN, reranking, HyDE. Any MCP-connector binding or `settingSources: ['user']`. A `sources` table with bodies. Linear document read-through. The revalidation sweep. Notion or Confluence.

### v0.5.4: use it deliberately for a week, and let the instruments earn their keep

**Delivers.** Binary judge with `evals/rubric.md` plus `rubric_hash`, cross-tier judging, `needs_review` only. `case.yaml` provenance fields stamped by `promote-case.ts`. The eval gate on pass^k with a tolerance band, a per-case definition hash and the corpus version, printing the measured flake rate. One new scheduled job: the two expressible queues digested into `#ops`. Watchdog invariants that survived spike 8, with invariant 1 corrected and the stuck-`running` check added. One labelling sitting producing binary labels, gold source URIs and promoted cases over the same traces. Then a week of genuine daily use through the capture path, with STATUS.md's findings ledger as the deliverable.

**Proves it works on the live wire.** Serve turns in `obs.db` rise materially above 35. Human feedback rows rise above 1. Five consecutive no-change `npm run evals` runs exit 0. The `#ops` digest arrives with counts that match a hand query. At least one new failure mode is promoted to a case, or the week is logged explicitly as "reviewed N traces, no new failure modes", which is itself the anti-ossification rule.

**Does not include.** The reflective diff proposal. Definition A/B. The console review lane. TPR/TNR calibration. Any second agent, handoff, or channel adapter. Anything Slack beyond the one email, which should be sent on day one of v0.5.0 so the clock starts while the code gets written.
