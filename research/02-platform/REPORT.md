# Deep Research Wave 02: From Protocol Demo to Agent Platform

**Capable residents, agent engine, memory, sandboxes, observability, governance, evals, deployment**
Research date: August 16, 2026. Method: 11-dimension parallel research sweep over the leading agent-platform stacks (LangChain deep agents + Managed Deep Agents as the anchor inspiration, LangGraph runtime, LangSmith, the Anthropic Agent SDK stack, the OpenAI stack and its deprecation record, memory systems, sandboxing, governance engines, eval harnesses, durable-execution engines, agent-definition formats and workbenches). All schemas were copied from primary sources into per-dimension evidence files in [`notes/`](notes/); citations below of the form [01]..[11] point at `notes/01-deepagents.md` through `notes/11-agent-config-workbench.md`. Wave 01 (the protocol) is [`../01-protocol/REPORT.md`](../01-protocol/REPORT.md); this wave assumes its conclusions and designs on top of the shipped RFA substrate (hub 0.6.0, spec 0.1.6).

## TL;DR

**Everything RFA needs for the platform phase already exists as small, well-documented data shapes, and none of it needs a framework dependency.** Across all 11 dimensions the same pattern held: the durable value of each leading stack is a handful of schemas (a run tree, a feedback record, a checkpoint chain, a SubAgent manifest, a guardrail result, a reward file), while the platform hosting those schemas is closed, license-keyed, cloud-bound, or already deprecated. The market supplied its own verdict: OpenAI killed every hosted-config agent product within roughly a year (Assistants API, Agent Builder, Reusable Prompts, hosted Evals) while its code-first SDK survived [05]; LangGraph's server is a closed license-keyed wrapper over five documented tables [02]; self-hosted LangSmith is Enterprise-only ClickHouse-on-Kubernetes [03]. **Adopt the shapes, reject the platforms.**

**The Claude Agent SDK is Claude Code as a library and already ships nearly everything deepagents packages**: per-agent model/effort/tools/memory via AgentDefinition or hot-reloaded agent .md frontmatter, session resume, in-process MCP tools, a 30-event hook lifecycle, and the same OS-level sandbox open-sourced as `@anthropic-ai/sandbox-runtime` [04][07]. Upgrading residents is therefore an incremental swap of the `claude -p` shell-out, not a runtime build. **RFA's own primitives turn out to be the halves other stacks fake**: presence leases are the health probe, the durable room log is the approvals checkpointer, the evidence gate is a free eval labeler, and MemoryGate is the memory admission control none of the surveyed memory systems has [06][08][09][10]. The v0.4 design in section 3 is assembled entirely from adopt-verbatim schemas plus those existing primitives: directory-as-agent packs, a ~300-line supervisor with a SQLite runs/steps journal, layered memory in SQLite, srt sandbox tiers, LangSmith-shaped runs/feedback tables, the spec 12.2 gate with Cedar-style evaluation, computed-reward evals with pass^k, and a six-stage console workbench, all validated against a named first workload (Linear document drafting reaching rooms via CLI and Slack channels, section 3.10). Week one starts with a strict swap (Agent SDK residents + session resume, behind the existing tests) and then adds the first scaffolding: agent.md definitions and a supervisor.

## 1. The gap between what we have and a daily work tool

Wave 01 shipped the substrate: a Room Hub MCP server with rooms, presence leases, signed capability cards + digests, envelopes with origin stamping and dispositions, a tasks board with an evidence gate, moderation/room_admin verbs, human principals, OTel spans, memory-ingestion defenses, and a live console. The protocol works and is dogfooded daily (the resident pm-agent answers Goodvest product questions through a standing room).

What actually exists on the agent side is one hand-written process, and it defines the gap precisely (grounding: `dogfood/pm-agent.ts`, `STATUS.md`, [04][06][10][11]):

| Dimension | Today | Daily-work-tool bar |
|---|---|---|
| Agent brain | `spawn("claude", ["-p"])`, 180s SIGKILL, no cost/turn accounting | Agent SDK sessions: resume, interrupt, budgets, typed results with `total_cost_usd` |
| Agent definition | Hardcoded TS + env vars (`RFA_PM_MODEL`, `RFA_PM_KNOWLEDGE`) | Declarative per-agent files: model, effort, tools, skills, memory, sandbox, budgets, room bindings |
| Memory | In-process `Map` of last 8 truncated turns; dies on restart; 120KB knowledge pack re-sent per question | Durable layered memory (blocks, episodes, facts), background consolidation, gate-enforced writes |
| Runtime | `nohup`/terminal tab, no restart, no supervisor, no durable runs | Reconciled registry, crash-loop-aware supervisor, resumable runs, schedules |
| Sandbox | None (pm-agent has no exec, so nothing enforced) | Per-agent OS-level policy (network allowlist, fs rules), tiers for exec-capable agents |
| Governance | Spec 12.2 gate specified but unimplemented; approvals exist but no decision vocabulary, no budgets | Gate with recorded decisions, approve/edit/reject/respond approvals, per-agent cost/rate ceilings |
| Observability | Hub OTel spans (`rfa.{tool}`), console stream + graph | Run trees with cost/tokens, one feedback record, fixed dashboards, alerts |
| Evals | `npm test` + `npm run e2e` (wire scenarios) | Trajectory + computed-reward harness, baseline regression gate, pass^k reliability runs |
| Workbench | Read-only console (stream + animated graph) | Registry, editor, playground, approval inbox, runs view, lifecycle controls |

The strategic asymmetry: the hard, novel part (the protocol with capability discovery, presence, moderation, provenance) is done, and the remaining parts are the ones the rest of the industry has already converged on, in public, with copyable schemas. Wave 02's job is selection and assembly, not invention.

## 2. The landscape

### 2.1 Deep agents (the anchor): four pillars RFA already runs, one convention worth stealing

LangChain's deepagents is Claude Code reverse-engineered into middleware: the July 2025 blog names the four pillars (detailed system prompt, no-op todo planner, isolated-context subagents, filesystem), and `graph.py` shows the fixed assembly order (Skills -> Filesystem -> SubAgents -> Summarization -> PatchToolCalls -> user middleware -> profile extras -> tool exclusion -> prompt caching -> Memory -> HITL) [01]. Since RFA residents run ON Claude Code, they already have the pillars natively; taking deepagents as a dependency would be a harness inside a harness. What transfers is structure:

- **The SubAgent shape** (name, action-oriented description, system_prompt required with NO implicit inheritance; tools/model/skills/permissions/interrupt_on/response_format optional) and its anti-context-bloat contract: the delegator receives ONE final report, never the peer transcript.
- **Context-hygiene numbers**: tool results over 20k tokens evict to `/large_tool_results/` with a 10-line preview; human messages over 50k evict head/tail; summarization triggers at 85% of max input keeping ~10%; an on-demand `compact_conversation` tool.
- **interrupt_on HITL**: per-tool `true | false | {allowed_decisions: [approve, edit, reject, respond], when: predicate}`, checkpointer mandatory, resume via `Command(resume={decisions: [...]})`.
- **Managed Deep Agents' capabilities-as-files convention**: an agent is a directory; only `agent.py` is required; instructions.md, skills/, connectors/, channels/, schedules/, memory.py, sandbox/, evals/ each enable a capability by existing. Instructions and skills sync so prompt edits land without redeploy. The channels flow (verify + normalize event -> resolve identity + thread -> run -> post back to the same thread) is the exact spec for room-driven resident runs.
- **Harbor-format evals**: per-task dirs where a verifier writes a numeric reward to `reward.txt`/`reward.json`; the reward-file contract is runner-agnostic.

### 2.2 LangGraph runtime: a five-table durable engine hiding inside a licensed server

The entire LangGraph Platform data model is five resources with fully documented schemas: **assistants** (versioned named config over one graph: immutable versions, full-payload updates, `setLatest` promote/rollback), **threads** (status idle|busy|interrupted|error), **runs** (pending|running|error|success|timeout|interrupted, per-thread mutex of 1 concurrent run, `multitask_strategy: reject|interrupt|rollback|enqueue` for double-texting, `afterSeconds`, webhooks), **checkpoints** (5-method saver interface `getTuple/list/put/putWrites/deleteThread` over a parent chain; errors/interrupts/resumes stored as writes with negative indices), and **store** (hierarchical namespaces, `$eq/$gt/...` filters, TTL) [02]. Streams are decoupled and resumable via persisted per-run buffers + `Last-Event-ID` cursors, which is the same cursor-replay pattern as RFA's `room_listen`. Infrastructure is deliberately boring: Postgres holds ALL durable data, Redis holds nothing durable ("no user or run data persists in Redis": a worker wake-up sentinel, cancellation, stream pub/sub) [10]. On one Mac, SQLite takes the Postgres role and the hub's own push takes the Redis role. The server itself is closed and license-keyed (`LANGGRAPH_CLOUD_LICENSE_KEY`); the schemas are in the notes.

### 2.3 LangSmith: four small contracts, one indexing trick, one dead-end self-host

The durable value is four data contracts [03]: (1) a **run tree** where every run carries `dotted_order` (`<start_time>Z<uuid>` per ancestor: lexicographic sort of one indexed string column = depth-first trace traversal, no recursive CTEs); (2) one universal **feedback record** `{run_id, key, score, value, comment, correction, feedback_source.type: api|app|evaluator|model}` shared by humans, judges, and code checks; (3) the **example/experiment triangle** with `source_run_id` provenance (production failure -> corrected example -> regression test); (4) the ecosystem-standard **evaluator contract** `({inputs, outputs, referenceOutputs, run}) => {key, score, comment}`. OTel interop is first-class (GenAI semconv maps onto run fields; `langsmith.span.kind` etc. as escape hatches). The MIT npm packages **agentevals** (trajectory match: strict/unordered/subset/superset with per-tool arg-match overrides, pure code, no API key) and **openevals** (judge factory + 12 exported prompt constants) work standalone. Self-hosting is Enterprise-only ClickHouse + Postgres + Redis + ACE on Kubernetes: a clear reject, while the prebuilt dashboard's six fixed sections and five alert metrics are a ready-made console spec.

### 2.4 The Anthropic stack: the runtime RFA already pays for

The TypeScript Agent SDK is literally the Claude Code harness as a library: `query()` spawns the bundled CLI and reads the same `~/.claude` auth and project config the current shell-out uses, so migration is incremental [04]. What it adds over `-p`:

- **Control surface**: `interrupt()`, `setModel()`, `setPermissionMode()`, `getContextUsage()`, `streamInput()`; `startup()` pre-warms the subprocess so a standing resident answers with zero spawn latency; `SDKResultMessage` carries `total_cost_usd`, per-model `modelUsage`, `num_turns`, `permission_denials`.
- **Per-agent settings, twice with one schema**: SDK `AgentDefinition` and hot-reloaded `.claude/agents/*.md` frontmatter (`model`, `effort` low..max, `tools`/`disallowedTools` incl. `mcp__*` patterns, `permissionMode`, `maxTurns`, `skills`, `mcpServers`, `memory: user|project|local`, `isolation: worktree`, `background`). The only surveyed format with first-class effort [11].
- **Sessions**: `resume: sessionId` restores full context from JSONL transcripts (prompt-cache reuse replaces re-sending the 120KB knowledge pack), `forkSession` branches.
- **In-process MCP tools**: `createSdkMcpServer` + `tool(name, desc, zodShape, handler)` puts RFA room verbs inside the resident process as `mcp__rfa__*`, permission-scopable.
- **Permissions**: a fixed 6-step pipeline (hooks -> deny -> ask -> mode -> allow -> canUseTool); deny rules hold even in `bypassPermissions`; `canUseTool` returns `{behavior: 'allow', updatedInput}` (native edit-before-approve). One trap governs the whole approval design: in `dontAsk` mode the `canUseTool` step is skipped and the tool is denied [04][08], so `dontAsk` and human-in-the-loop approvals are mutually exclusive. The unattended-but-approvable posture is `default` mode + explicit allow rules (no prompting on the routine surface) + deny rules + ask rules for the tools that genuinely need a human.
- **Hooks**: 30 lifecycle events with `session_id`/`agent_id`/`prompt_id` join keys; command hooks block via exit code 2.
- **Memory**: `memory: "project"` gives each agent `.claude/agent-memory/<name>/` with the MEMORY.md index protocol; the GA client-side memory tool `memory_20250818` (view/create/str_replace/insert/delete/rename under `/memories`) has a ready TS handler [06].
- **Sandbox**: the SDK `sandbox` option plus standalone `srt` (Seatbelt on macOS, bubblewrap on Linux, host-side proxy domain allowlists); Anthropic reports sandboxing cut permission prompts 84% [07].
- **Agent teams** (experimental, interactive-only): shared task list + JSON mailboxes, inter-agent messages explicitly untrusted and unable to approve permissions. Convergent validation of RFA's design, not a substrate: no discovery, no presence, no capability cards, never spawns under `-p`/SDK.

Managed Agents (Anthropic-hosted loop) is rejected on local-first grounds; the SDK covers everything on the Mac.

### 2.5 The OpenAI stack: a deprecation record and five surviving primitive shapes

The loudest signal in the whole sweep is what OpenAI killed [05]: Assistants API (dead 2026-08-26), Agent Builder (visual canvas, launched Oct 2025, deprecated June 2026, off 2026-11-30, guidance: "export to Agents SDK code"), Reusable Prompts and the hosted Evals platform (both off 2026-11-30; the evals migration guide points at open-source Promptfoo). Code-in-repo definitions outlive platform state. What survived, and is worth copying as shapes:

- **Handoff**: a plain tool named `transfer_to_<agent_name>` with `{tool_name, tool_description, input_json_schema, input_filter, is_enabled}`; `input_filter` rewrites the history the receiver sees. Crucially, OpenAI's own server-managed conversations do NOT support input filters: owning the transcript client-side is what preserves composability. RFA's hub-owned transcript is a real advantage; never trade it for vendor state.
- **Two composition modes, named**: handoff (history transfers, new agent owns the conversation) vs `Agent.as_tool()` (subroutine, caller keeps the thread, with built-in `needs_approval: bool | predicate`). RFA ask/serve is the as-tool mode; handoff is missing today.
- **Guardrails**: `GuardrailFunctionOutput {output_info, tripwire_triggered}` with a placement grammar (input = first agent only, output = last only, tool = every call) and a `run_in_parallel` flag. One default to invert: blocking for side-effecting agents.
- **Session protocol**: 4 methods (`get_items/add_items/pop_item/clear_session`), SQLite file-backed default.
- **Trace taxonomy**: `agent_span`, `generation_span`, `function_span`, `guardrail_span`, `handoff_span`, trace header `{workflow_name, trace_id, group_id, metadata}`, `trace_include_sensitive_data` flag.
- **Grader JSON shapes** (`string_check`, `text_similarity`, `score_model`, `python`, `multi` weighted expressions) plus the trace-grading idea: graders run over full run traces, not IO pairs.
- **Temporal integration** as a pattern: deterministic orchestration + every model/tool call as a retryable activity with `start_to_close_timeout`; adoptable as per-tool `{timeout_ms, retry}` declarations without adopting Temporal.

### 2.6 Memory systems: assembled from four proven parts

The surveyed systems converge on one taxonomy (CoALA: working/episodic/semantic/procedural) and one decay pattern (consolidation-by-rewrite, never automatic score decay) [06]. The parts that compose into the winning local-first design:

- **Letta memory blocks**: five fields (`label, description, value, limit, read_only`) compiled into the prompt as an XML rendering with chars_current/chars_limit; attachable to multiple agents. Sleep-time agents do background consolidation.
- **Mem0's two-phase pipeline with exact JSON contracts**: extraction returns `{"facts": [...]}`; reconciliation returns `{memory: [{id, text, event: ADD|UPDATE|DELETE|NONE, old_memory?}]}` against an id-keyed candidate list; md5 hash dedupe; SQLite history log of every event; `expiration_date` TTL. Paper numbers: +26% vs OpenAI memory on LOCOMO, 91% lower p95 latency vs full context, and the graph variant adds only ~2%: the quantitative case against a graph database.
- **Graphiti/Zep's bi-temporal columns**: `created_at/expired_at` (transaction time) and `valid_at/invalid_at` (event time), `episodes[]` provenance, contradiction = invalidation, never deletion; LLM-free retrieval (Zep paper: LongMemEval +18.5% at ~90% lower latency).
- **Claude's memory tool** (`memory_20250818`) as the agent-facing interface, with the auto-injected "ASSUME INTERRUPTION" protocol prompt and the documented multisession pattern (start by reading memory, end by updating it).
- **RFA's existing MemoryGate** (Jaccard shingles, cross-sender near-duplicate detection) is the admission layer none of the above has; the gap is that pm-agent memory is a process-local Map that dies on restart.

### 2.7 Sandboxing: srt as the free Tier 1, containers for the hostile tier

`@anthropic-ai/sandbox-runtime` is the same Seatbelt+proxy mechanism Claude Code uses, usable as a TS library (`SandboxManager.initialize(config)` then `wrapWithSandbox(cmd)`), with a settings JSON worth copying verbatim: `network.allowedDomains` (allow-only, all denied by default) and `filesystem.denyRead/allowRead/allowWrite/denyWrite` (reads deny-then-allow, writes allow-only) [07]. It always write-blocks shell configs, `.gitconfig`, `.git/hooks/`, and `.claude/commands/` regardless of config, and its README documents its own bypass classes: it is a prompt-injection blast-radius reducer, not a hostile-code container. Deepagents reduces every sandbox provider to one interface (`execute(command) -> {output, exit_code, truncated}`, file ops derived), which keeps E2B/Modal/Vercel as swap-in options later. For real CPU/RAM caps on a Mac only containers deliver (`docker run --cpus/--memory/--pids-limit/--network none`; apple/container on macOS 26 gives per-container lightweight VMs). Deno `--no-prompt` with scoped `--allow-net/--allow-read` is the cheapest untrusted-TS interpreter (never `--allow-run`/`--allow-ffi`).

### 2.8 Governance: a tiny closed vocabulary, pluggable checks, and RFA is already halfway there

Every mature platform separates the decision vocabulary from the check implementation [08]. Cedar (in Bedrock AgentCore) evaluates tool calls with TOOL ARGUMENTS in context (`context.input.amount < 500`) under a three-line algorithm (any forbid => DENY; else any permit => ALLOW; else DENY), implementable in ~200 lines of TypeScript. Claude Code's six-step permission order is the closest production model, with mandatory reason strings and hook denials that survive even bypass mode. LlamaFirewall reduces every scanner to `{decision: ALLOW|BLOCK, reason, score}`. LiteLLM's budget shape (`max_budget, budget_duration, tpm/rpm limits`, lagged sweep enforcement, containing scope beats inner scope) proves per-token real-time accounting is unnecessary. guardrails-ai's mutation vocabulary (`fix`, `reask`) is the anti-pattern for an append-only log. The audit convergence (IETF draft-sharif-agent-audit-trail): log input, model+config hash, tool sequence, output, overrides, memory ops, cost; tamper evidence = a hash chain over RFC 8785 canonical JSON, and RFA already ships a JCS canonicalizer (`src/jcs.ts`). RFA's spec 12.2 (`allow | alert | hold | refuse`) already matches the industry vocabulary; only the evaluation algorithm, check plug-in shape, and decision record are missing.

### 2.9 Evals: computed rewards first, judges last, and RFA owns the two hardest assets

The harnesses that work (tau-bench, SWE-bench, terminal-bench) all put a computed verifier first [09]. tau-bench's reward is `r = r_action x r_output` in {0,1} (final DB state hash match x required-substring match), and its **pass^k** metric (`E_task[C(c,k)/C(n,k)]`, the chance ALL k trials succeed) exposed that gpt-4o scored ~61% pass^1 but <25% pass^8 on retail: consistency is the scarce property in a daily tool. SWE-bench's dual test sets (FAIL_TO_PASS goals + PASS_TO_PASS invariants) generalize to "protocol lints alongside the goal check". terminal-bench puts the verifier beside the task in a task directory. Braintrust contributes the file convention (`*.eval.ts`, one CLI, `--watch`) and the baseline-diff gate, which works locally without CI. agentevals/openevals provide the TS scorer layer standalone, with a documented seam (`judge` parameter) for a `claude -p` judge under Claude Code auth. RFA already owns replayable NDJSON trajectories (every room log) and a human-verified evidence gate (spec 10.2 verify verdicts), which are the two assets every eval platform tries to manufacture.

### 2.10 Engines and deployment: no external engine needed at one-Mac scale

The single highest-value durable primitive is the **memoized step**, identical in Inngest (`step.run(id, fn)`: "the response is saved in the function run state and the step will not re-run") and Restate (`ctx.run(name, fn)` journaled): implementable in under 200 lines over SQLite [10]. Temporal's workflow/activity split collapses for RFA because the brain is a `claude -p` subprocess (a whole turn is one opaque activity); `claude -p --resume` session ids substitute for context replay at zero cost. Hatchet contributes doctrine (durable tasks only wait and spawn; everything else in journaled steps). kagent's value is the record shape: a fully declarative Agent CRD continuously reconciled by a controller, collapsible into local `agents/*` files watched by a supervisor. Cloudflare's Agents SDK has the best per-agent runtime interface surveyed (lifecycle hooks, embedded SQLite, a typed `schedule()` API worth copying verbatim). Local supervision is a solved problem: launchd keeps ONE supervisor alive (`KeepAlive{Crashed:true, SuccessfulExit:false}`, `ThrottleInterval 10`), and the supervisor implements pm2's proven policy vocabulary (`max_restarts`, `min_uptime`, exponential backoff, `kill_timeout`, `wait_ready`). RFA's presence leases beat HTTP liveness probes: a live process with a stale lease is wedged by protocol definition. Restate (single brew-installable binary, RocksDB) is explicitly parked as the designated upgrade if the home-built journal ever runs out.

### 2.11 Agent definition formats and workbenches: files won, canvases died

Across seven formats, the winner for a solo git workflow is markdown-frontmatter files in a directory-as-agent layout: Claude Code's frontmatter is the richest per-agent knob set (and the only one with first-class `effort`), MDA's "a file's location determines its role" convention beats both single-file and server-record formats [11]. LangGraph assistants contribute one discipline (full-payload snapshots, no partial merges) without the server-side store. Letta's `.af` warns against mixing state into definitions (diffs become meaningless), while its ADE contributes the best workbench idea surveyed: the Context Window Viewer (see exactly what is in a running agent's context). AutoGen's component JSON instantiates classes by `provider` path on load ("ONLY LOAD COMPONENTS FROM TRUSTED SOURCES" is a self-indictment): definitions must be inert schema-validated data. agent-inbox's whole HITL integration surface is four tiny types (`HumanInterrupt {action_request, config {allow_accept/edit/respond/ignore}, description?}` / `HumanResponse {type, args}`). Nobody surveyed has cost ceilings in the definition, and nobody has room bindings at all: both stay RFA differentiators.

## 3. Synthesis: the RFA v0.4 design

The platform is nine components around the existing hub, plus the named workload that validates them (3.10). Each element below is marked **ADOPT** (verbatim schema from evidence), **ADAPT** (shape kept, implementation changed), or **BUILD** (new, but small and traced to a need). Constraints honored throughout: TypeScript, MCP-native, local-first on one Mac, solo operator, Claude models via the owner's existing Claude Code auth, RFA protocol as the substrate, personal Goodvest work tool.

### 3.1 Agent definition: the resident pack

**ADOPT [11][01][04]: directory-as-agent + markdown-frontmatter definition.**

```
agents/<name>/
  agent.md          # YAML frontmatter (definition) + markdown body (system prompt)
  skills/           # agentskills.io-compatible SKILL.md folders (loaded via the plugin bridge below)
  knowledge/        # markdown packs (replaces the RFA_PM_KNOWLEDGE env hack)
  memory/           # the ONE agent memory root: blocks/ (Letta-style .md) + notes/ (free-form); see 3.3
  evals/            # per-agent eval cases (section 3.7)
  state/            # runtime state, gitignored (member id, session ids, room cursors, memory.db)
```

**The skills-loading bridge [04], stated because the naive reading is wrong:** SDK skill discovery is filesystem-only. Skills load from `.claude/skills/` (governed by `settingSources`) or from plugins; there is no option to load them from an arbitrary directory, so `agents/<name>/skills/` does NOT "just load". The runner therefore registers each pack as a local plugin (`plugins: [{type: "local", path: "agents/<name>"}]`), which makes the pack's `skills/` discoverable in place with no file moves. Residents keep `cwd` at the repo root, so `settingSources: ["project"]` keeps resolving to the repo's single `.claude/` settings surface (a per-pack `cwd` would silently retarget project settings and CLAUDE.md resolution). Fallback if plugin loading proves brittle: symlink pack skills into `.claude/skills/<agent>--<skill>/`.

Frontmatter schema (one zod schema in `src/agentdef.ts`, shared by runner and console; draft in [11]): `rfa_agent` format version; `name`, `description` (feeds the capability card); `model` + `effort` (Claude Code semantics, ADOPT verbatim); `tools.allow/deny` incl. `mcp__*` patterns; `mcp_servers`; `skills`; `knowledge` globs; `memory {scope, blocks, gate: memory-gate REQUIRED, enforced as specified in 3.3}`; `sandbox {isolation: none|worktree|container, permission_mode, network, cwd}` compiling to srt fields; `secrets` (secret NAMES only, values resolved by the supervisor at spawn, section 3.4); `budgets {max_turns, max_execution_s, max_rpm, max_retries, per_task_usd, per_day_usd}`; `interrupt_on` (deepagents shape with `allowed_decisions`); `rooms[] {room, role, serve, presence_ttl_s, auto_resume}` (BUILD: the RFA-specific moat, nothing surveyed has room bindings); `schedules`. Two deliberate deltas against the [11] draft, so the two documents stop diverging silently: budgets split the notes' single `max_usd_day` into `per_task_usd`/`per_day_usd` (the two-layer enforcement in 3.6 needs both), and `sandbox` gains the `network` field (the three-mode compile target of 3.4); [11] stays authoritative for everything else.

**ADOPT [02][11]: assistant-style versioning, git-backed.** Full-snapshot discipline (LangGraph's no-partial-merge rule); the runner stamps the `agent.md` content hash into presence/card metadata at start; promote/rollback = `git checkout`. No version database. The capability card and digest are DERIVED from `{name, description, skills, rooms[].serve}`, so a definition edit rotates the digest and is visible in the roster: MDA's versioning-without-redeploy with git replacing Context Hub [01].

**ADAPT [01]: SubAgent contract at two levels.** Inside a resident, Claude Code native Task subagents (already isolated-context). Across residents, delegation via the RFA task board with the deepagents contract made a spec-level rule: the delegator receives ONE final, optionally schema-typed report, never the peer transcript.

### 3.2 Engine/runtime: Agent SDK residents under a tiny supervisor

**ADOPT [04]: the Agent SDK replaces the `claude -p` shell-out.** `query({prompt, options})` with `resume: sessionId` per conversation (kills the 120KB knowledge re-send via prompt-cache reuse), `permissionMode: "default"` with explicit allow/deny rules plus ask rules for `interrupt_on` tools (3.6 explains why not `dontAsk`), `maxTurns`/`maxBudgetUsd` rails, `settingSources: ["project"]` (so the owner's personal `~/.claude` config never leaks into residents), `startup()` pre-warm for standing residents, and `createSdkMcpServer` handing room verbs (`mcp__rfa__room_send`, `room_task`, roster lookup) to the model in-process. Record `total_cost_usd`, `modelUsage`, `num_turns`, `permission_denials` into envelope/task metadata. Structured serve answers via `outputFormat: json_schema`.

**BUILD [10] (~300 lines): `src/supervisor.ts`.** Reads the registry (`agents/*/agent.md`), reconciles continuously (file watch, kagent's controller loop without Kubernetes), spawns residents in fork mode with pm2's policy vocabulary (`autorestart`, `max_restarts`, `min_uptime`, exponential backoff, `kill_timeout` SIGTERM-drain-SIGKILL, `wait_ready` over IPC once the room is joined). launchd keeps only the supervisor and the hub alive (two plists: `RunAtLoad`, `KeepAlive{Crashed:true, SuccessfulExit:false}`, `ThrottleInterval 10`). **Health = presence leases, not probes**: live process + stale lease = wedged = SIGTERM + restart.

**ADOPT [02][10]: durable runs and steps in SQLite.** `data/runs.db` mirroring LangGraph's exact field names and enums (RunStatus `pending|running|error|success|timeout|interrupted`; ThreadStatus `idle|busy|interrupted|error`; max 3 attempts), with the per-thread mutex and `multitask_strategy: reject|interrupt|rollback|enqueue` for double-texting a busy resident. Wake-up is the hub's existing `room_watch`/tasks push (the Redis sentinel role); the room itself is the stream (the Redis pub/sub role). **ADAPT [02]: the checkpoint payload** for subprocess residents: keep the 5-method saver interface, make the payload `{claude_session_id, cwd, room_cursor, custom_state}` with a parent chain; `claude -p --resume` is the resume mechanism, the row makes it durable and forkable. **ADOPT [10]: the memoized step** in the client SDK: `ctx.step(id, fn)` journaled to `steps(run_id, step_id, seq, result_json)` with Inngest replay semantics, plus `ctx.sleepUntil` and `ctx.waitForMessage` mapped to `room_listen`; keep the API name-keyed and Restate-compatible so a later adapter is mechanical. **ADOPT [01]: context-hygiene numbers in the RoomMember SDK**: payloads/tool results above ~20k tokens offload to files with a first-10-lines preview, references travel in envelopes; monitor resident context health against the 85% threshold via `getContextUsage()` + existing OTel spans; a supervisor force-compact action between tasks.

SIGTERM -> finish the in-flight serve turn, release floor, lapse lease -> respawn from new code; the new signed card digest in the roster IS the deployed-version marker (Restate's immutable deployments mapped onto an existing RFA primitive). ### 3.3 Memory: layered, gated, background-consolidated

One directory + one SQLite DB per agent, mapped to the CoALA layers [06]:

- **L0 working**: the Agent SDK context window. Nothing to build.
- **L1 core blocks (ADOPT Letta)**: `memory/blocks/*.md` with front matter `{label, description, limit, read_only}`, compiled into the system prompt in Letta's XML rendering with chars_current/chars_limit; limit enforced on write; one block attachable to several agents later.
- **Agent-facing writes (ADOPT Anthropic), with ONE root and stated enforcement**: the `memory_20250818` tool backed by an in-process TS handler whose `/memories` prefix maps to `agents/<name>/memory/` and nowhere else (`blocks/` for L1, `notes/` for free-form), with the documented return-string conventions and mandatory path-traversal validation as-is; the episodic/semantic DB sits beside it as gitignored `state/memory.db`. SDK `memory: "project"` is NOT enabled for residents: it would open a second, ungated root at `.claude/agent-memory/<name>/`; instead the pack compiler reproduces the MEMORY.md index protocol inside the canonical root (a `MEMORY.md` whose head is loaded at session start). Because the handler is RFA code, the manifest's `gate: memory-gate` is enforced IN the handler: every `create`/`str_replace`/`insert` payload passes MemoryGate, block `limit` and `read_only` are checked on `blocks/*.md` writes, and a rejected write returns an error string to the model instead of touching disk. Defense in depth: a PostToolUse hook matching `Write|Edit` on any memory path denies file-tool writes that bypass the handler (exit 2), so the gate holds even for residents that also carry general file tools.
- **L2 episodic (BUILD, shapes from [06])**: append-only `episodes` table; every gated room message (with the MemoryGate verdict and `wrapped` boundary form stored) and every own answer is an episode.
- **L3 semantic (ADOPT Mem0 + Graphiti)**: `facts` table maintained by Mem0's exact two-phase contract (extraction `{"facts": [...]}`, reconciliation `{memory: [{id, text, event, old_memory?}]}`), with Graphiti's bi-temporal columns (`created_at/expired_at/valid_at/invalid_at`), `supersedes` lineage, `episode_ids` provenance, md5 hash dedupe, and a `source_origin` trust tier from envelope provenance (BUILD: agent-derived facts excludable from high-trust prompts). DELETE is invalidation, never row deletion. Retrieval: FTS5 BM25 reranked by recency x importance (Generative Agents shape, importance rated once at consolidation); sqlite-vec only if recall proves insufficient.
- **L4 procedural**: prompts, skills, knowledge stay git-tracked; consolidation may PROPOSE diffs, a human applies them. Auto-writing procedural memory from room content is the worm channel spec 14.3 exists to close.

**Consolidation is background-only** (Letta sleep-time / LangMem background formation): triggered after N gated exchanges or on a timer, as a separate tool-less cheap `claude -p` call; never in the answer path. **MemoryGate stays the single admission door**; every episode stores the verdict; consolidation reads only `wrapped` content. The Anthropic multisession pattern (start by reading memory, end by updating it) becomes the standard working-agent protocol. The OpenAI 4-method Session protocol (`get_items/add_items/pop_item/clear_session`) is the RoomMember conversation-memory interface [05].

### 3.4 Sandboxes: tiered, srt-first, execute() behind one interface

**ADOPT [07]: srt as Tier 1, embedded as a library**, with the srt settings JSON verbatim as the manifest's sandbox block (no new policy vocabulary), stored per agent and surfaced on the capability card for governance. Wrap the whole resident subprocess (local agent-in-sandbox: LangChain's objections do not apply on one Mac): `allowedDomains: ["api.anthropic.com", <agent APIs>]`, `denyRead: ["~/.ssh", "~/.aws", "dogfood/state"]`, `allowWrite: [<workspace>, "/tmp"]`. **Spike required**: hub reachability on `localhost:8790` through srt's proxy (`allowedDomains: ["localhost:8790"]`, `allowLocalBinding`). If the spike fails, Tier 1 does not block on it: the fallback is tool-in-sandbox instead of resident-in-sandbox (wrap only `execute()` subprocesses with `wrapWithSandbox(cmd)`), which keeps hub connectivity outside the sandbox and still honors the one-shared-HTTP-hub working rule.

Tiers: **0** MCP-only, no exec (pm-agent today); **1** srt-wrapped exec (default); **1.5** Deno `--no-prompt` with scoped `--allow-net/--allow-read` for untrusted TS snippets (never `--allow-run`/`--allow-ffi`); **2** disposable `docker run --rm --network none --cpus 2 --memory 2g --pids-limit 256` per task for hostile code (apple/container when on macOS 26); **3** cloud burst deferred behind the same interface. **ADOPT [07][01]: the deepagents backend interface** for the exec tool: `execute(command) -> {output, exitCode, truncated}` with file ops derived; `SrtLocalBackend` and `DockerBackend` now, E2B/Modal/Vercel as future drop-ins. **ADOPT and extend srt's always-blocked write list** as an RFA invariant: shell configs, `.git/hooks`, `.claude/commands`, plus `dogfood/knowledge/`, agent manifests, and `data/`. Budgets, honestly: wall-clock timeout + output truncation + max-concurrent-execs at the `execute()` boundary (recorded in OTel spans); hard CPU/RAM caps only at Tier 2; token budgets belong to the engine. **ADAPT [07]**: Vercel's three-mode UX (`sandbox.network: none|allowlist|open`, `open` requiring room_admin override) compiled to srt fields; never `bypassPermissions` + `allowUnsandboxedCommands` [04]. srt is a blast-radius reducer, not a hostile-code boundary: that is what Tier 2 is for.

**BUILD [01][10]: the solo-operator secrets story.** Capable agents with tool access means per-agent MCP tokens and external API keys, and MDA's runtime checklist names identity/credential management as a core engine feature [10]; the sandbox rule is absolute: "Never put secrets inside a sandbox" [01]. Design: secret VALUES live in exactly one place, a gitignored `data/secrets.json` (or the macOS Keychain via `security`, behind the same lookup interface), readable only by the supervisor and covered by `denyRead` in every srt policy. Packs declare secret NAMES in the manifest (`secrets: [LINEAR_API_KEY]`), never values, so `agents/` stays committable. At spawn the supervisor resolves names to values and injects them per resident: as entries in the SDK `env` option, constructed explicitly because `env` REPLACES the subprocess environment [04], which here is the feature: a resident receives ONLY the variables its manifest names, never the owner's full shell env; and as headers/env inside that agent's `mcpServers` configs. Tier 2 containers receive no secrets at all: when a hostile-code job needs a credentialed call, it happens host-side through an in-process `mcp__rfa__*` tool, never by handing the container a token. Multi-user credential isolation (a second human's keys) stays deferred; this is the single-operator floor, not the ceiling.

### 3.5 Observability: two tables and a bridge

**ADOPT [03]: the LangSmith run shape + `dotted_order` verbatim, in SQLite.** `runs(id, trace_id, parent_run_id, dotted_order, name, run_type, status, error, start/end, project, inputs, outputs, tags, input_tokens, output_tokens, cost, reference_example_id, needs_review)`; the existing `rfa.{tool}` OTel spans and SDK/engine calls bridge in via the already-propagated traceparent. Lexicographic sort of one indexed column = the whole trace-tree UI. **ADOPT [03]: the feedback record, plus one RFA extension** (`{run_id, key, score, value, comment, correction, source_type}`; LangSmith's source enum is `api|app|evaluator|model`, and RFA adds `human` so console and room principals are distinguishable from API writers): console thumbs, judges, and code checks all write the same row; dashboards, alerts, and the review lane are generic over it. **ADOPT [05][03]: naming discipline**: OpenAI's span taxonomy (`agent_span/generation_span/function_span/guardrail_span/handoff_span`), `group_id` = room/thread, a `trace_include_sensitive_data` flag, and GenAI semconv attributes (`gen_ai.request.model`, `gen_ai.usage.input_tokens/output_tokens`) so any future export (LangSmith cloud, Langfuse) stays a config change while traces stay local by default (Goodvest data never dual-writes to a vendor).

**ADOPT [03]: fixed console panels from LangSmith's prebuilt sections** (traces/errors/latency, LLM calls, cost + tokens per trace, top-5 tools, top-5 feedback keys) and three alerts only (error pct, avg latency, avg feedback score; 5 or 15 minute windows), delivered as messages into an `#ops` RFA room (the hub alerting through its own protocol) with LangSmith's webhook auto-field list as the payload shape. **BUILD [08]: hash-chain the event log**: each event gets `prev_hash` = SHA-256 over the JCS canonical form of the previous event (`src/jcs.ts` exists), plus cost and policy-outcome fields. **ADAPT [03]: annotation queues to a single review lane**: a `needs_review` flag, rubric feedback keys, keyboard next/prev, and an add-to-dataset-with-correction button writing an example row with `source_run_id`. **ADAPT [03]: retention tiering to a vacuum policy**: keep runs with feedback or `in_dataset` forever, prune the rest after N days; the sweeper and the backup job that pairs with it live in 3.9.

### 3.6 Governance and budgets: implement spec 12.2, extend approvals, two-layer ceilings

**ADOPT [08]: the gate, with Cedar's algorithm adapted to default-allow.** Keep `allow | alert | hold | refuse` exactly. Evaluate all matching checks; the effective outcome is the most severe (refuse > hold > alert > allow); checks are independent; default allow when nothing matches (default-deny stays at the tool layer: explicit allow/deny rules with `canUseTool` denying anything unmatched, not the message layer). Check plug-in shape `{id, match, tier, outcome|outcome_map, timeout_ms}` with three tiers: `rules` (in-process declarative match with the WHOLE envelope as context, Cedar's parameter-gating insight), `command` (subprocess, envelope JSON on stdin, LlamaFirewall's `{decision, reason, score}` on stdout, exit 2 = refuse), `prompt` (`claude -p` cheap-model screening, alert/hold tiers only, never refuse). **Mandatory decision record** per gated event: `{gate, check_id, reason, score?, elapsed_ms}` + gate-config hash, appended to the log; `alert` emits a supervisor-visible system event without blocking. **Fail-closed to hold** (never silent-allow, never hard-refuse) reusing the existing 5-minute hold TTL and release/expiry events; no role or mode bypasses a refuse check. Refuse-tier checks always block; parallel evaluation only for alert-tier (inverting OpenAI's default for side-effecting agents [05]).

**ADOPT [01][08][11]: approvals with the four-decision vocabulary.** Extend the approval ext with `allowed_decisions: [approve, edit, reject, respond]` and `expires_at`; `room_admin approve` gains an optional params override (edit-before-approve), recorded; expiry resolves as reject via a log-derived sweep that survives restarts (RFA's durable log IS the checkpointer LangGraph requires). Engine bridge, with the mechanism stated exactly because it is easy to get wrong: the bridge only fires if the tool call actually reaches `canUseTool`, and in `dontAsk` mode that step is skipped and the tool denied [04][08], so residents with any `interrupt_on` entry run `permissionMode: "default"`, and `interrupt_on` compiles to ask rules (or a PreToolUse hook returning `permissionDecision: "ask"`), which route to `canUseTool` even when an allow rule matches. A gated tool call then makes `canUseTool` publish a `HumanInterrupt`-shaped approval request into the room (agent-inbox's four types verbatim), block on the intervention event, then return `{behavior: 'allow', updatedInput}` or `{behavior: 'deny', message}`. The console renders pending approvals as accept/edit/respond/ignore cards. `needs_approval: bool | predicate` is added to serve-capability declarations [05]. Every check emits a `GuardrailFunctionOutput`-shaped record (`{name, output_info, tripwire_triggered}`) into envelopes and OTel spans [05].

**ADOPT [08]: two-layer budgets, LiteLLM shapes.** Engine layer (cost): per-agent `{per_task_usd, per_day_usd, max_turns, max_parallel_tasks}` from Agent SDK usage, checked at task pickup and run completion (lagged enforcement is fine; LiteLLM sweeps every 10 minutes); on exceed the agent refuses with reason `overloaded` and LiteLLM's exact `spend=X budget=Y` detail format. Hub layer (rate): per-member `rpm` and `max_pending_requests` in room policy with a new `rate_limited` error carrying `retry_after_s`. Precedence documented deliberately: the containing scope (room) caps the member scope, as team-over-key in LiteLLM. The resident permission posture follows from the bridge above: `default` mode + explicit allow rules for the routine tool surface + deny rules + ask rules for `interrupt_on` tools; `dontAsk` is legal only for a resident whose manifest has no `interrupt_on` entries at all.

**BUILD [04]: the account layer above both.** Every resident, the `claude -p` judge, consolidation passes, AND Paul's own interactive Claude Code sessions share one subscription, and its binding resource is rolling usage windows, not dollars: `total_cost_usd` is a client-side estimate [04], useful as a relative weight between agents, never as the real meter. Three mechanisms: (1) a supervisor-global concurrency cap (max N Claude turns in flight across ALL residents and background passes) with a priority order: pending approvals and human-facing serves take slots first, scheduled jobs next, consolidation/evals/judges last and preferably off-hours, so background work never burns the window Paul is actively using; (2) on a subscription rate-limit error the run parks as `interrupted` with the provider's retry-after, the resident answers `refuse` with reason `overloaded`, and the supervisor pauses task pickup account-wide until the window clears (one shared signal, no per-agent retry storms); (3) the per-agent USD/turn budgets remain as the fairness knob inside the cap, and the tier-3 judged eval cadence stays cost- and count-bounded (3.7) for the same reason.

### 3.7 Evals: computed-reward harness over room logs

**BUILD [09] (one pure function): `src/evals/trajectory.ts`.** `rfaLogToTrajectory()` maps a room NDJSON slice (filter by conversation or task id) to OpenAI-style messages with `room_task`/admin verbs as synthetic `tool_calls`, so every agentevals evaluator (match modes AND judge) runs unmodified over room logs. **ADOPT [09][03]: agentevals + openevals as npm deps used standalone**, standardizing every scorer on `{key, score, comment}`.

**ADOPT [09]: tau-bench's computed reward as the primary score**: `r = r_state x r_output x r_protocol`, where `r_state` = expected final task-board state + `verification.verdict == accept` + evidence present, `r_output` = `must_mention` substrings in the subject's responses, `r_protocol` = lints as pure functions over raw events (reply-by honored, no `gone_quiet`, atomic claims, citations present, no memory-gate bypass). LLM judge only where semantics are irreducible. **ADOPT: SWE-bench dual sets** (goals + invariants: a case that meets the goal while violating an invariant fails) and **pass^k with the exact estimator** (n >= 4 trials, report pass^1 and pass^4) for reliability-tier runs. **ADOPT: terminal-bench task-as-directory**: `evals/cases/<id>/` with `case.yaml` (kind live|replay, subject by capability, scripted or LLM asker, expect blocks, budgets, trials; full schema drafted in [09]), seed fixtures, `reference.ndjson`. **ADOPT: Braintrust's file convention + baseline diff without the platform**: `evals/*.eval.ts`, `npm run evals` writes `reports/evals/<ts>.json` + markdown and exits nonzero on regression vs `evals/baseline.json` (the CI gate without CI, respecting the CI deferral).

**BUILD [09]: the evidence-gate flywheel**: `scripts/promote-case.ts <room> <task-id>` slices the NDJSON around a real verify verdict into a labeled eval case: the dataset grows from real work at zero annotation cost. **ADAPT [09][03]: the judge transport**: keep `TRAJECTORY_ACCURACY_PROMPT` wording and the result shape, swap the model init for a `claudeJudge()` shelling `claude -p --output-format json` (Claude Code auth, no API key); extend the rubric with RFA bullets (consulted the room, correct kinds, proper refusals, citations, no fabricated evidence); score with `choices: [0, 0.25, 0.5, 0.75, 1]` for stability; cap judge calls per day (LiteLLM-style counter instead of spend caps). Run cadence: tier 1 replay-only deterministic scorers inside `npm test` (free, milliseconds); tier 2 `npm run evals` live scripted cases on a scratch hub with the baseline gate (pre-commit, minutes); tier 3 `npm run evals:judged` weekly or after prompt/model/knowledge changes (LLM asker + judge + pass^k, cost-bounded).

### 3.8 Console/workbench: six shippable stages on the existing hub console

**ADOPT [11]**, each stage shippable alone, all served next to `GET /console` (no second frontend stack):

1. **Registry tab**: list `agents/*/agent.md` via the shared zod schema; card digest, bound rooms, live presence from leases, definition hash, running/stopped from the supervisor.
2. **Editor**: form view AND raw-YAML view of the same file (AutoGen's dual-view rule: the file is canonical, the form is a lens); shows the derived capability-card digest diff before save.
3. **Playground tab** (LangSmith pattern, minimal): run one question through the serve code path without a room; show answer, latency, cost; later side-by-side comparison of two definitions (haiku/medium vs sonnet/low).
4. **Inbox tab**: pending `HumanInterrupt` approvals across rooms with accept/edit/respond/ignore, header badge. Reuses section 3.6 machinery.
5. **Runs tab**: trace trees from the runs table (`ORDER BY dotted_order`), the fixed metrics panels of 3.5; stretch goal is Letta's Context Window Viewer (show the exact assembled prompt per run, logged by the runner).
6. **Lifecycle controls**: start/stop/restart from the Registry, health from presence leases.

**ADAPT [05]: write-surface auth, shipped WITH stages 2/4/6, not after them.** Stages 2, 4 and 6 turn a read-only page into a mutating control plane (definition edits, approvals, process control), so they carry an authentication design from day one: ChatKit's session-token shape adapted onto spec 4.2 human keys. The browser never holds a long-lived credential; the operator presents the provisioned `human_key` once, the hub mints a short-lived session token bound to `{principal, scope}`, and every write (editor save, approval decision, lifecycle action) carries that token. Because the token chains to a provisioned human key, the hub stamps the resulting events `origin: "human"`: a browser approval therefore counts as human-origin under spec 4.2 (which is what makes the 3.6 approval flow sound), instead of being an anonymous HTTP POST that any local process could forge. The hub keeps binding to localhost today; the token design is what keeps stages 2/4/6 safe the day the console leaves localhost. Read-only tabs stay tokenless.

### 3.9 Deployment: two plists, one manifest

**ADOPT [10]**: launchd keeps the hub and the supervisor alive (`RunAtLoad`, `KeepAlive{Crashed:true, SuccessfulExit:false}`, `ThrottleInterval 10`, `StandardOutPath` logs, `launchctl bootstrap/kickstart` control); everything else is supervised children. **ADOPT [02]**: an `rfa.json` deployment manifest modeled on `langgraph.json` (residents map, env, checkpointer/store TTL sweeper configs, http toggles). pm2 is an acceptable day-one interim, never the end state (no lease-aware health, no drain protocol). The whole design ports as-is to the eventual small server (SQLite -> Postgres is a driver swap on the same schemas; the LangGraph field names were kept for exactly this).

**BUILD [03]: retention and backup, because the whole point is accumulated knowledge.** Every store in this design grows without bound on one Mac: runs/steps/feedback rows, per-agent episodes and facts, NDJSON room logs, and the `~/.claude` JSONL transcripts every session leaves behind. Retention, as a sweeper configured in `rfa.json`: runs older than N days are pruned unless they carry feedback or are `in_dataset` (the 3.5 vacuum policy); facts are never row-deleted (invalidation only, per 3.3) and episodes are the provenance they point at, so both are kept, but room NDJSON rotates and compresses after M days once journaled; Claude transcripts are deleted when their session id no longer appears in any live checkpoint row. Backup: one nightly launchd job runs SQLite `.backup` on every DB and writes a dated archive of `data/`, `agents/*/memory/`, and `dogfood/state/` to a Time Machine-covered path; the restore procedure is a runbook entry in STATUS.md and is exercised once, not assumed. A daily work tool that loses its accumulated memory to one dead SSD was never a work tool.

### 3.10 The first real workload: how Goodvest work reaches rooms

The brief's endpoint is capable expert agents doing daily Goodvest work, so v0.4 names its target workload explicitly; otherwise the eval cases, budgets, and sandbox tiers of 3.4-3.7 have nothing real to validate against and the platform machinery stays self-referential.

- **Resident 2, `linear-scribe` (BUILD: the first capable agent beyond pm-agent).** It drafts Goodvest Linear documents (expression de besoin, spec produit, spec design) from pasted transcripts and briefs, reusing the existing goodvest-linear-* skill packs as pack skills. Tools: `mcp__linear__*` plus Read/Grep; the Linear token is a supervisor-injected secret (3.4); Tier 0 at first, Tier 1 when it grows exec. Its `interrupt_on` is the approval design's first real test: every `mcp__linear__save_*` call pauses on an approve/edit/reject card (3.6), so nothing lands in Linear unreviewed; edit-before-approve is exactly the review motion a PM already performs. Its budgets get sized against observed usage, not guesses.
- **Channels (ADOPT [01]): how work arrives.** The MDA channels flow is already the room-run seam (3.2); v0.4 ships two concrete channels plus schedules: (a) a CLI entry point `rfa ask <room> <question>` (the `/ask-pm` generalization), joining with the operator's `human_key` so requests are human-origin; (b) a Slack channel adapter following the flow verbatim: verify + normalize a mention/DM -> resolve principal + thread (a persisted thread-to-conversation map) -> post into the room -> resident serves -> post the answer back to the SAME Slack thread (Slack is MDA's documented provider, which is why the flow was copied); (c) `schedules` for recurring runs, starting with a morning digest of open questions and stale tasks into the room.
- **The flywheel closes on this workload (3.7).** Every verified linear-scribe run is `promote-case.ts` material; the first eval cases are "expression de besoin from this transcript" with a computed reward (document created in the right team, required sections present, citations back to the source text), which is exactly the `r_state x r_output x r_protocol` shape, and pass^k over it measures the consistency a daily tool actually needs.

## 4. What NOT to do (each traceable to a documented failure)

- **Do not build or buy a visual workflow builder.** OpenAI deprecated Agent Builder about 8 months after launch and shuts it off entirely at about 13, with "export to SDK code" as the exit; AutoGen Studio self-labels "research prototype"; Dify's DSL stores canvas coordinates as config [05][11].
- **Do not store agent definitions as server-side records or hosted prompts.** Assistants API and Reusable Prompts are both dead with "move config into your application code" as official guidance. Files in git, capability cards as a runtime projection [05][11].
- **Do not take deepagents/langchain/langgraph as dependencies.** A harness inside a harness under Claude Code; every pillar already ships natively. Steal the shapes [01].
- **Do not add Redis, Postgres, ClickHouse, Kubernetes, or Docker-mandatory ops at one-Mac scale.** LangGraph's own docs confirm Redis holds nothing durable; self-hosted LangSmith is Enterprise Helm-on-K8s; kagent is a controller for a cluster that does not exist here [02][03][10].
- **Do not adopt Temporal (even start-dev), Inngest, or Hatchet as engines.** The brain is a subprocess, so a whole turn is one opaque activity; Inngest inverts control (engine calls your endpoint), which contradicts long-lived residents; Hatchet drags Postgres. The memoized step is ~200 lines of SQLite; Restate is the designated upgrade if that ever runs out [10].
- **Do not use a graph database for memory.** Mem0's own paper shows the graph variant adds ~2% on LOCOMO; Graphiti's bi-temporal columns capture the valuable part in plain SQLite [06].
- **Do not extract memory in the hot path, and never auto-update procedural memory from room content.** Latency per exchange, and the Morris-II worm channel respectively; background consolidation + human-reviewed diffs only [06].
- **Do not hard-delete memories on contradiction.** Invalidate with timestamps; a moderated multi-agent space needs "who said what when" answerable [06].
- **Do not trust vendor-side conversation state.** OpenAI's server-managed conversations silently disable handoff input filters; the hub-owned transcript is what makes RFA handoffs filterable and auditable [05].
- **Do not run refuse-tier checks in parallel with delivery, and do not adopt mutation-style guardrail outcomes (`fix`/`reask`).** An optimistically delivered message cannot be recalled; rewriting content inside the delivery path breaks append-only semantics and hides policy effects from audit [05][08].
- **Do not give room agents `bypassPermissions`, and never combine it with `allowUnsandboxedCommands`.** The documented dangerous pair; `default` mode + explicit allow/deny/ask rules + sandbox is the unattended posture, and `dontAsk` is reserved for residents with no `interrupt_on` entries because it skips `canUseTool` and silences approvals [04][07][08].
- **Do not treat srt as a hostile-code boundary.** Its README documents bypass classes (proxy-ignoring programs, unfenced DNS, Unix-socket grants); hostile code goes to Tier 2 containers [07].
- **Do not build judge-only evals or per-token budget accounting.** Every harness that works puts computed verifiers first; LiteLLM proves lagged sweeps suffice [08][09].
- **Do not build a standalone second workbench app or a custom dashboard builder.** Grow the hub-served console; fixed panels cover a solo operator [03][11].
- **Do not let definitions execute code on load.** AutoGen's provider-class-path JSON is the cautionary tale; definitions are inert data validated by one zod schema [11].

## 5. Suggested build path (v0.4.x)

Each milestone is independently shippable and verified by the existing `npm test` / `npm run e2e` discipline plus the new eval tiers as they land.

**v0.4.0, the week-one cut. Items 1-2 are the strict swap (behavior-identical, no new subsystems); items 3-5 are the first scaffolding, labeled honestly as such:**
1. Swap `dogfood/pm-agent.ts` to Agent SDK `query()` (model, `maxTurns`, `maxBudgetUsd`, `permissionMode: "default"` + explicit allow rules, `settingSources: ["project"]`); record `total_cost_usd`/`modelUsage`/`permission_denials` into envelope metadata. The #1 migration gotcha [04]: the SDK's default system prompt is MINIMAL, not Claude Code's, so a behavior-identical swap must pass either the current PM prompt explicitly or `systemPrompt: {type: "preset", preset: "claude_code", append: ...}` (CLAUDE.md only loads with the preset plus `settingSources` including `"project"`). Verify parity against a handful of recorded answers before calling it identical.
2. Per-conversation `resume: sessionId` replacing the conversation Map; move `dogfood/knowledge/` behind Read/Grep (or a skill) instead of prompt-stuffing [04].
3. `agents/pm-agent/agent.md` + `src/agentdef.ts` zod schema; capability card + digest derived from the definition; the runner stamps the definition hash into presence metadata [11]. Known side effect: deriving the card rotates the LIVE dogfood room's digest once; announce it in the room and re-verify the roster pin the same day (digest rotation is the designed versioning signal of 3.1, but this first one is a migration event, not an edit).
4. `src/supervisor.ts` v0 (spawn, restart policy, lease-based health) + two launchd plists. `rfa agents reload` as versioned drain [10].
5. The srt spike: verify hub reachability on `localhost:8790` through the proxy; write pm-agent's (trivial, Tier 0) sandbox block anyway so the manifest field exists. If the spike fails, fall back to tool-in-sandbox (wrap only `execute()` subprocesses via `wrapWithSandbox`) so Tier 1 is never blocked by the one-shared-HTTP-hub rule [07].

**v0.4.1, engine + memory:** SQLite `runs`/`steps`/`schedules` tables (LangGraph enums, memoized step, Cloudflare schedule API); multitask_strategy on resident threads; in-process `mcp__rfa__*` tools via `createSdkMcpServer`; memory v1 (blocks + the in-process `memory_20250818` handler enforcing MemoryGate, block limits, and read_only at the single 3.3 root + episodes table with gate verdicts; a PostToolUse `Write|Edit` hook denying memory-path writes that bypass the handler) [02][04][06][10].
