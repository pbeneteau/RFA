## TL;DR

**The unit of parallelism is the run, never the turn, and every shipping product agrees: 12 of 12 surveyed products keep the agent loop serial, 10 of 12 isolate workspaces per run, and the two that do not (Amp, opencode) leave writer collisions to the user [01].** The turn lock is permanent architecture, not a transitional patch. What changes is everything around it: the live probes [07] establish that one resident process CAN drive N concurrent `query()` calls (distinct session ids, true overlap at 9951 ms and 7572 ms from one start instant, zero cross-contamination), at the cost of one full `claude` CLI child process per concurrent run, and that the load-bearing invariant is at most one live writer per session id (concurrent resume of one id is documented corruption: JSONL branch forking and mid-write truncation that crashes the CLI [05]).

**Probe A overturns a piece of house doctrine and rescues two DECIDED recommendations the critic had voided.** On SDK 0.3.233, `canUseTool` DOES fire for the built-in Write when Write is in `tools` but NOT in `allowedTools`; a bare `allowedTools` entry auto-approves before the callback and the SDK names the shadowing in a warning (`CLAUDE_SDK_CAN_USE_TOOL_SHADOWED`) [07]. So the CLAUDE.md "MCP tools only" rule is version-specific, a path guard on Write/Edit is implementable in the callback under strict conditions, and the write fence becomes two doors: the callback (semantics-aware, hosts the claim-fence check and the notify-and-repair channel) plus the already-vendored, currently unwired OS sandbox `@anthropic-ai/sandbox-runtime` (the only door that covers Bash, whose arguments no callback can trace) [02][07]. Section 2.2 names the losing verdicts.

**The three contradictions the critic found are resolved with one verdict per state.** Rung 5's conflict handling becomes a lifecycle (section 2.1): clean publish lands through git under the board's existing verification authority; a conflict while the run is live returns into the run as tool-result feedback (the only mechanism with measured wins over both locks and OCC: within 5 percent of serial correctness at 1.4x speedup versus OCC at 0.93x and 1.83x tokens [06]); a conflict after the run ended becomes a presented branch; note 02's MERGE_HEAD/abort rules are the crash contract underneath all of it. The per-run workspace is a CoW clone of the pack directory, not a git worktree (a worktree materializes tracked files only, and the pack's mutable bulk is gitignored by design, so a worktree is an empty shell [02]); the pack subtree map in section 2.3 places `state/` and /memories OUTSIDE the clone as shared surfaces, which also dissolves the live-SQLite-WAL tearing hazard by construction.

**Five defects in shipped code are prerequisites, not concurrency features, and two of them race today under zero parallelism.** `FactStore.apply` is a cross-process check-then-insert TOCTOU between the resident's consolidation timer and `rfa agent reflect --apply` (the exact silent-duplicate shape of Mem0 issue #6531) [04]; consolidation's watermark has no cross-process guard [04]; the module-level `currentLease` makes the keepalive renew only the newest lease and the finally release the wrong one under any widening (section 3); the per-day budget check-at-pickup, debit-at-completion pattern has a race window the width of a whole model call, with worst case N times the remaining day budget for a pack with no `per_task_usd` (section 5); and approval cards have no consumption identity, while Resume Means Resume measures cross-process double-fire of a parked interrupt (the approval card's shape, per note 06's mapping; the paper probed Python orchestration frameworks) at 10 of 10 attempts with no ceiling below sixteen racers, repairable only by a uniqueness-constraint claim at the durable-state read path (section 9) [06].

**The ladder gains one rung nobody proposed and loses none outright.** Candidate parallelism (N independent runs of one task, one selected, the rest discarded) has no shared-state conflict by construction, and RFA already owns the missing piece, verification authority (wire 10.4); the measured cost is selection (CodeMonkeys: 69.8 percent coverage collapses to 57.4 after selection; M1-Parallel: early-stop needs no selector and buys 1.6-2.2x latency) [06]. The remote boundary survives with four amendments (section 8): resource keys need an authority segment or the 10.3 extension is a one-call guest DoS; chain-id cycle detection is advisory and the hub must default `reply_by` on cross-home requests; the lease-release-while-blocked fix is a precondition for admitting remote peers, because a peer can freeze a default account (effective cap 2, not 3) at zero model cost; and the spec gains an explicit eight-item list of guarantees that are local-only.

## 1. The invariant, and what the live probes settled

Every rung below rests on one invariant, stated once: **an agent's loop is serial per session; concurrency is more runs, each with its own SDK session, its own workspace surface, and its own lease; at most one live writer per session id, and per-conversation FIFO is preserved.** The evidence is unanimous across twelve products [01], the actor runtimes (Orleans turns, Dapr per-actor locks, Temporal per-execution serialization) [05], and the memory systems (Letta's documented "not thread-safe, use separate conversations", 409 CONFLICT on overlap) [04]. Two corrections to the brief's framing land here:

- **Sessions CAN fork** (`forkSession: true`, new id, copied history, tail-only, no merge primitive), so rung 2's justification was wrong; its conclusion survives on the corrected ground that a conversation key owns a session id and one session id tolerates one writer [05]. Cognition's implicit-decisions argument is the citable basis for serial-within-one-thread-of-intent [01].
- **In-process concurrency is process-level fan-out.** Each active `query()` spawns its own `claude` CLI child (two children observed during the overlap run), so `agents.max_inflight` and host sizing must budget one full CLI process per concurrent run [07].

Probe B also confirmed concurrent resume of DISTINCT sessions in one process: both resumed, correct per-session recall, no errors. Same-session concurrent resume was deliberately not probed and stays PARKED (trigger: any design wanting intra-conversation parallelism) [07].

The read-only rung carries a price tag: Anthropic measured parallel research subagents at roughly 15x chat token use (softened to 3-10x in 2026 guidance), so N concurrent runs must drain one per-agent budget pool [01]; section 5 makes that pool honest.

## 2. The three contradictions, resolved

### 2.1 The rung-5 conflict lifecycle: one verdict per state

Three notes reached DECIDED verdicts that contradict each other: [01] rec 4 (completion presents a branch, never auto-merges), [02] rec 4 (publish runs a real git merge with MERGE_HEAD/abort semantics), [06] rec 1 (replace merge-time resolution with notify-and-repair into the live run). The resolution is a lifecycle, because the three verdicts answer three different states:

| State at publish | Verdict | Winning evidence |
|---|---|---|
| Merge clean (run live or ended) | **Merge lands automatically** on the shared tree: commit on the run branch first, merge second, task completion still passes the board's verification authority (wire 10.4), branch recorded on the task; no live context is needed when there is no conflict to repair | [02] git machinery; the review gate the surveyed products implement as a human PR is, in RFA, the existing verification act |
| Run live, merge conflicts | **Notify-and-repair**: the conflict returns into the run as tool-result feedback while its context is live; the run repairs and re-publishes; abort only on repair failure | CoAgent: notify beats 2PL (1.04x, 0.81 deadlocks/trial) and OCC (0.93x, 1.83x tokens) at 1.4x speedup within 5 percent of serial correctness [06] |
| Run ended, merge conflicts | **Presented branch** to the operator or a designated sequential integration turn | [01] rec 4; there is no live context to notify, and Atomix's granularity result says abort-and-retry is only cheap at action-phase granularity, not run-sized [06] |
| Crash mid-publish | **[02]'s contract**: publish starts from a clean tree, MERGE_HEAD marks the in-progress state, `git merge --abort` rolls back, and recovery is a reconcile loop over observed worktree-plus-board state ([03] R9), never unlock cleanup | git first-class crash semantics [02]; Kubernetes controller pattern [03] |

Losing verdicts, named: **[01] rec 4 loses its "never auto-merges" absolute for the clean case.** Its 10-of-12 evidence describes products whose only reviewer is a human on a PR; RFA's board already separates completion from verification, so refusing clean merges would duplicate a gate that exists. **[06] rec 1 loses for the run-ended case**: notify-and-repair requires a live context. **[02] loses nothing but its implicit assumption that conflicts are resolved at merge time by the publish step**; under the lifecycle the publish step only detects, and either the run or a human resolves. Expected conflict rates go into the spec so nobody writes "rare": 27.67 percent of real AI-agent PRs conflict, about 9.9 percent at 2-line median churn and near 30 percent at 25 lines (AgenticFlict, 107,026 simulated merges) [06].

### 2.2 The interception door: two doors, not one, and the conditions on each

The critic's gap 2 was correct against the notes as written: [03] R8 and [06] recs 1/9 placed load-bearing checks in `canUseTool` while the repo doctrine said built-ins never reach it, and [02] built its verdict on that doctrine. Probe A settles it with data [07]:

- On SDK 0.3.233, `canUseTool` fires for the built-in Write when Write is in `tools` and NOT in `allowedTools`; the deny sticks and no file is written. With `allowedTools: ['Write']` the callback is never consulted, the file is written, and the SDK emits `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED`, whose text also warns that settings-file allow rules shadow invisibly.

One verdict: **the write fence is two doors.** Door one is the callback, reached by fall-through: guarded built-ins (Write, Edit) are declared in the pack's base `tools` set and never bare in `allowedTools`; the resident asserts this at pack load and treats the shadowing warning as a fail-closed startup error. One caveat carries weight: probe A exercised Write only, so Edit's interception is assumed by analogy, not measured, and the shadowing assert does not cover the failure mode where Edit simply never reaches the callback on some SDK version (the OS sandbox would still hold the path guard, but the claim-fence token check would silently vanish for Edit-based mutations). The resident startup therefore runs a dry-run deny probe through the callback for EACH guarded built-in on the installed SDK version, failing closed like the shadowing assert; shipping rung 5 without that self-check, or without an equivalent explicit probe of Edit, is not an option. The callback hosts the per-run path guard, the claim-fence attempt check ([03] R8: a write whose claim moved to attempt N+1 is token 33 arriving after token 34), and the CoAgent-style footprint/notify channel [06]. Door two is the OS sandbox: `@anthropic-ai/sandbox-runtime` (Seatbelt on macOS, bubblewrap on Linux) is already in `package.json` with a typed policy in `src/execbackend.ts`, imported by no production module (only its own test, test/execbackend.test.ts); wire it around the resident with allowWrite = the run's scratch surface and denyWrite = pack tree, knowledge clones, `.rfa/` [02]. Door two is the only door for Bash, because a Bash command's write set cannot be traced from arguments; Claude Code's own worktree isolation refuses untraceable command shapes rather than pretending to trace them [01].

Losing verdicts, named: **[02]'s framing that "a canUseTool path guard guards nothing that matters" and [01] rec 3's "never by canUseTool" are refuted for Write/Edit on 0.3.233** under the fall-through condition. Both remain true for anything bare-listed in `allowedTools`, for settings allow rules, for harness-internal tools, and for Bash; and the CLAUDE.md record shows the callback's built-in behavior has already changed once across SDK setups, which is exactly why door two is DECIDED rather than optional: the OS fence is the version-proof layer. The nesting rule rides along: detect and refuse loudly when the sandbox cannot establish itself (a hub inside Docker), never degrade silently [02].

### 2.3 The run workspace is a CoW clone, and the pack subtree map

**Ruled in [02]'s favor.** A git worktree materializes tracked files only; the hub template gitignores `.rfa/`, `agents/*/state/` and knowledge clones, so the pack's mutable bulk is untracked by design and a worktree of it is an almost empty shell. The mechanism is a filesystem CoW clone (`cp -c` on APFS, `cp -r --reflink=auto` on btrfs/XFS, plain copy fallback on ext4), measured at 1.45 s for 9,721 files / 457 MB on the dogfood machine, with git kept for merge-back of the tracked subset only [02]. **Losing verdict, named: [01] rec 5 (worktree-per-run plus a `.worktreeinclude` copy list) loses on mechanism**; its warm-start concern survives and is answered better by the clone, which carries untracked state by construction. Claude Code's worktree choice is right for repos whose bulk IS tracked; an RFA pack is the opposite shape.

The critic's live-SQLite hazard (a mid-transaction CoW copy of a WAL database captures a torn db/-wal/-shm triple) is resolved by construction, not by checkpointing: **the state directory is never cloned.** The subtree isolation map, which is also the answer to gap 4 (where memory lives relative to a per-run workspace):

| Pack subtree | Per-run clone? | Run access | Why |
|---|---|---|---|
| Pack definition, prompt, tracked docs | Cloned (CoW) | Read-only | Tracked, tiny; the git subset for merge-back history |
| Working files a rung-6 pack mutates | Cloned (CoW) | Read-write in the clone; publish via the section 2.1 lifecycle | The isolation target |
| `scratch/<runId>/` | Created fresh per run | Read-write | The run's declared write set; the fine-grained resource its claim names ([03]) |
| `knowledge/<name>-clone/` | **Excluded**; exposed read-only at its stable path | Read-only (denyWrite in door two) | Sync is `git pull --ff-only`; a dirty clone wedges it ([02] rec 3); section 6 governs the reverse race |
| `state/` (memory.db WAL, episodes, facts) | **Excluded**; shared across the pack's runs | Never via file tools; via the memory verbs only | One store per identity; live WAL files must never be CoW-copied mid-transaction; DB snapshots only via `better-sqlite3` `db.backup()` |
| /memories file store | **Excluded**; shared | `mcp__memory__*` verbs under section 4's contract | The cross-conversation surface by design (Letta: core memory is shared across all conversations [04]) |
| `.rfa/` (hub directory state) | Not a pack subtree; never visible to runs | None | Hub-owned |

The consequence stated plainly: **the per-run clone isolates the workspace, and deliberately does not isolate memory.** Memory is shared across a pack's concurrent runs and governed by the verb contract of section 4; anything else silently creates the diverging-replica worst case inside a single process.

## 3. Prerequisite defects in shipped code

These are ordered before any rung because they are wrong today or become wrong at N=2:

1. **`FactStore.apply` TOCTOU (live today).** The resident's consolidation timer and `rfa agent reflect --apply` both open FactStore on one `state/memory.db`; `apply` is a SELECT-then-INSERT with no transaction and a non-unique hash index (src/memoryfs.ts:358-371). Fix: one better-sqlite3 transaction plus a UNIQUE partial index on `hash WHERE expired_at IS NULL` [04].
2. **Consolidation is single-flight by hope (live today).** The watermark read-process-write (src/consolidate.ts:104-152) has no cross-process guard; make the watermark update compare-and-set or take a consolidation lease row [04].
3. **`currentLease` is module state** (src/resident.ts:152, :577, :762). Under two concurrent turns the keepalive renews only the newest lease (the older expires mid-turn and is swept, silently raising effective concurrency past the cap) and the first finally releases the second turn's lease. Per-turn local, and the keepalive renews every live lease the process holds (cost-accounting gap analysis).
4. **Run-state reconciliation at zero traffic.** Any run whose process died must be swept to a terminal state by a direct state check, not a rate alert; Claude Code's stuck-forever background tasks are the failure class [01], and the CLAUDE.md zero-traffic rule already names the principle.
5. **Approval-card consumption semantics** (section 9): canonical action identity, a shared-store read-path claim, an effect class. This one is a prerequisite because the supervisor already restarts residents and parallelism multiplies deliveries into the consume window.

## 4. Memory under parallel turns: verbs, ownership, ordering, provenance

The shipped-systems answer is unanimous: serialize or partition writes, never merge, and no production system merges two diverged agent-memory replicas at all (the survey's strongest negative result) [04]. RFA's mechanism, layered:

- **Per-verb contract on /memories, not one coarse lock.** Appends stay concurrent; `strReplace` keeps its accidental optimistic concurrency (unique `old_str`) on purpose; `insert`, `create`-overwrite and `delete` gain a fail-if-changed precondition (content hash) whose error tells the model to re-read. `create()` today clobbers unconditionally (src/memoryfs.ts:88-89); it becomes create-exclusive or the loser survives as a named conflict file, Syncthing-style, never silently discarded [02][04].
- **Ownership by tool declaration (the sleep-time split).** Destructive verbs (strReplace on `blocks/*`, delete, rename) belong to the consolidation lane only; answer-path turns keep view plus append-shaped verbs. This is Letta's shipped two-writer design, enforced the way RFA already enforces everything: tools are the declaration [04].
- **Gate ordering.** A gate-skipped fact today vanishes with `return "skipped"`; MemClaw measured a synchronous near-duplicate gate rejecting 206 of 400 contradictory writes before the contradiction detector ever saw them, capping detection at 0.490. Record every gated skip (hash, similarity, episode ids) so consolidation sees contradiction-shaped near-duplicates [04].
- **Provenance on file writes.** Facts carry `source_origin` and `episode_ids`; /memories files carry nothing, and the writer easiest to manipulate is the one with the least provenance. Every file mutation records run, conversation, lane, and (section 8) hub-derived `requester_home` [04].
- **Poisoning scales with lanes.** MINJA reaches 98.2 percent injection success through queries alone; N parallel conversations are N injection sequences in the time of one, and the cross-org variant needs only to be READ by a concurrent turn, not to survive consolidation [04]. The quarantine rule of section 8 is the concurrency-specific defense.

Replica memory merge stays PARKED (trigger: the first writing replica pair); if opened, merge at the facts layer only, where bi-temporal close-not-delete is order-tolerant, and copy StateFuse's contract (conflicts become durable surfaced objects, resolvers may abstain, never silent last-writer-wins). LWW or CRDT text merge for /memories files is REJECTED; Letta documents whole-block rewrite as lost updates and says designate an owner [04].

## 5. Cost accounting under parallel runs

**The per-day budget is a check at pickup and a debit at run completion, so the race window is the whole model call, and no mutex can close it without re-serializing.** Under N concurrent turns all N read the same stale `spend.usd` (src/resident.ts:556-570, debit at :721/:757); with `per_task_usd` declared the worst case is N-1 whole task ceilings beyond serial admission; with no `per_task_usd` (schema-legal, warning-only) each run's ceiling is the whole remainder, so `per_day_usd: 5` at N=4 admits a roughly 20 dollar day. Three adjacent holes ride along: `currentLease` (section 3), crash-forgetting of the in-memory debit, and replicas-as-distinct-members each owning a private ledger, so a 5-dollar agent deployed as three replicas is a 15-dollar identity.

The decision, from the dedicated gap analysis:

1. **Move the ledger into `runs.db` as a two-phase reservation inside the existing `acquire()` IMMEDIATE transaction** (src/account.ts:228-272), the module whose own header states the rule this extends: one transaction decides admission, never two sources that can disagree. An `agent_spend(agent, day, settled_usd)` table plus `reserved_usd` and `spend_day` columns on `account_leases`: admission computes committed = settled plus live reservations, refuses with a new `budget_exhausted` reason (mapping to the RFA-0.5 sect 18.3 `overloaded` refusal) when the remainder is below viability, and otherwise reserves `min(per_task_usd, remaining)` and returns the granted ceiling, which `brainTurn` passes as `maxBudgetUsd`, deleting the duplicate local computation. `release(leaseId, actualUsd)` settles the real cost and frees the rest in one transaction. Reservations ride the lease, so the existing sweep reclaims them for free. The correction to the critic's framing: admission cannot debit actual cost, because cost is unknown until the result message; reservation-then-settle is the atomic shape. Pessimistic reservation is cheap at measured spend: the dogfood hub's obs DB (`<hub directory>/.rfa/data/obs.db`, re-read 2026-08-25) records $24.26 lifetime across 643 agent spans, $16.54 of it one eval day (2026-08-19), with every other day between $0.47 and $2.18 against $3-5 day caps. The gap analysis's original figure ($2.65 across 433 spans) could not be reproduced from that DB at fix time and is withdrawn; the conclusion holds under either figure.
2. **Exhaustion policy: finish-the-turn, refuse-the-next, never kill mid-turn.** Under reservations no live run is ever over its granted ceiling, so "which of N stops" is unaskable by construction; exhaustion surfaces only at the next `acquire`, and `waitForSlot` returns a budget refusal immediately (like `account_paused`) instead of polling out the asker's deadline. A refused run holds nothing; a budget-stopped run keeps releasing its board claim with a why-note exactly as today. Lowering `per_day_usd` mid-day affects new admissions only.
3. **Attribution for honest meters.** `engine.failRun` records no cost and generic brain errors write NULL-cost obs rows, which is exactly where parallel-overshoot forensics will look; carry `runCostUsd` on every error path, give `failRun` a cost parameter, and persist lane, granted `ceiling_usd` and `spend_day` at settle (leases are deleted on release, so this is lost today). Reconciling summed obs cost against `agent_spend.settled_usd` is the honesty check itself.
4. **Gate `concurrency: N` on a declared `per_day_usd`** (or an imposed default): a pack with no ceiling goes from unbounded-serially to unbounded-times-N, and a warning is not a control at N > 1.

PARKED: supervisor back-fill of `settled_usd` from `runs.cost_usd` on sweeping a dead lease (trigger: first crash mid-run with material recorded spend); whether replica fleets share an identity-level day budget (trigger: first real replica deployment; the SQLite ledger makes either answer a one-line key choice).

Spec impact: RFA-0.5 sect 18.1 becomes min(per_task_usd, per_day_usd - committed); 18.5's "the per-day ceiling remains lagged" is struck; 18.6 gains the reservation column and `budget_exhausted`; RFA-0.4 sect 7.4 layer 1's "(lagged enforcement)" is amended for the per-day layer.

## 6. Knowledge sync against running turns

`rfa knowledge sync` is `git pull --ff-only` in the clone while runs read the live clone paths mid-turn; nothing consults the residents first, and the failure surface needs no crash: cross-file mixture (one answer citing two corpus versions), torn single files, ENOENT on a listed file (the phantom-missing-fact shape that already cost a day once), and a half-pulled clone after a crash that matches no upstream commit while `countDocs()` reports healthy. This race arrives FIRST, on the safest rung, because read-only packs are the first to parallelize.

Decision (gap analysis): **serialize sync behind a pack-scoped drain barrier in the existing account lease table**, the one cross-process authority on "a turn is in flight": sync inserts a maintenance marker row with its own short TTL, new turn admissions for that pack queue while it exists, sync waits for the pack's leases to drain (bounded by lease TTL, so a crashed resident cannot wedge it), pulls, deletes the row. About a day of work, entirely inside machinery that exists. Plus a taint detector that survives any bypass (an operator's hand-run `git pull`): stamp each clone's HEAD into the run's retrieval record at turn start, compare at turn end, mark mismatches mixed-corpus. Hours.

- Per-run read-at-SHA pinning via `git worktree add --detach` snapshots of the clone is PARKED (trigger: measured drain waits exceeding one lease TTL, or multi-host replicas that stop sharing one lease DB). Worktrees are valid HERE, unlike for the pack tree, because a knowledge clone is fully tracked content; but today's `pin` is a bookkeeping label with no read machinery behind it (the CLI's "evals read this sha" wording overstates what `pinCorpus()` does), so this is days of new work touching `systemPrompt`, `knowledgeFiles`, retrieval-record path normalization, and resumed-session paths.
- Sync taking a board claim on the clone's resource key is REJECTED: the rung-7 intersection does not exist yet, sync is an operator CLI action and not a room member, and the board partitions work rather than serving as a lock service. Reopen only if sync itself becomes an agent-performed task.

## 7. The board: resource-keyed claims, amended

Rung 6 of the brief's ladder (partition at assignment; the board refuses intersecting claims) is confirmed by the strongest sources available: Omega's shared-state single-commit-point architecture, Nomad's shipped plan queue, FoundationDB's Resolver, DPBench's controlled measurement that a protocol-encoded ordering rule drives 90 percent zero-shot deadlock to zero while one round of agent negotiation does not help, and Cognition shipping fan-out only as isolated shards under one conflict-resolving coordinator after publishing the case against fine-grained parallelism [01][03][06]. The claim precedes the turn because a model turn is a minutes-long transaction: OCC's own authors say long read phases degrade to pessimistic locking, and CoAgent measured both classical poles failing (section 2.1's numbers) [03][06]. As adopted, with [03]'s amendments:

- `resources[]` on `claim`; prefix-or-equal intersection (Gray 1976 collapsed into the key); refusal with `task_conflict` naming the blocker; **refuse, never wait**, which with no-widening-while-held breaks hold-and-wait and circular wait at once, making deadlock structurally impossible.
- **Widening is a fresh mini-claim**, refused-not-queued, never damaging the grant already held; after 3 refused widenings the board offers a creator-approved reservation (Kung-Robinson's starvation fallback).
- **Canonical key rule**: one real resource, one key; a knowledge clone shared by two packs gets one root key, never two per-pack paths, or the intersection check admits two writers into one git tree (the concurrency twin of the one-fact-one-file rule).
- **Grants persist on the task object**; the process-local `claimTokens` Map is honest for a bearer secret and wrong for a grant whose job is refusing future claims after a restart. Ship `lease_expired` for stale tokens (declared since 0.1.x, thrown nowhere), and thread the fence into the mutation path (section 2.2's callback door): Jepsen's etcd analysis is the proof that a lock API without a resource-side check fails mutual exclusion in healthy clusters.
- Scope statement in the spec: **claims prevent write-write interference only**; write skew through disjoint write sets survives by construction (PostgreSQL SSI's canonical anomaly, measured live by CoAgent) and is owned by 10.4 verification and idempotent task design.
- Granularity guidance from Omega's measurements: coarse detection costs 2-3x in false conflicts, so per-run scratch dirs are what make fine claims true, and the two ship as one story.

PARKED with triggers: per-resource epochs (a grant outliving its task); FIFO claim queueing (measured refusal rate above roughly 0.2 per claim). REJECTED: full OCC for agent work (reopen if turns become sub-second); blocking lock-service waits on the board (reopen with the queueing trigger); hub-side read-set reconstruction over pack workspaces (S-Bus observes only 26.1 percent of references at the HTTP layer and resident file reads never traverse the hub; the parked half survives for hub-owned surfaces where p_hidden is zero by construction) [03][06].

## 8. The remote and cross-org boundary

The six dimension notes designed as if every participant were a local pack; RFA-0.6 admits members whose tools the hub never sees. The dedicated boundary pass found the designs survive with four amendments, one ordering constraint, and one honesty list.

**Cycle detection degrades safely only with two preconditions.** A non-conforming framework will not propagate the chain-id ext key, so detection fails open at every hop crossing such a member; the backstop is the `reply_by` clock, which is optional on the wire. Amendments: the hub SHOULD stamp a default bounded `reply_by` on any request crossing a `home` boundary when the sender omits it (the only cycle recovery that survives an arbitrary framework, because it lives on the hub); and the hub-visible 2-cycle (R asks A while A's request to R is unanswered) gets an advisory ext naming the pending request id, never a refusal, because counter-asks are the legitimate clarifying-question idiom. Chain ids remain advisory refusal hints and never an admission input. **The ordering constraint: [05] rec 4 (release or downgrade the account lease while a turn is blocked on an ask) is a precondition for admitting any remote peer into a room whose local members make nested asks**, because a peer can otherwise provoke a depth-2 chain and freeze the operator's whole account (effective default cap 2: `agents.max_inflight` in src/hubdir.ts:65 via the supervisor; DEFAULT_CAP 3 is only the no-supervisor fallback, a correction that also standardizes [01] and [06], which cited 3) for up to 120 s per window at zero model cost inside its `peer_rpm` budget. The same lease release must cover approval-card waits, which block exactly like asks (critic gap 10b).

**Resource keys need an authority segment or the 10.3 extension is a DoS primitive.** A flat namespace lets a guest claim `[""]` and block every local claim. The wire form: `room/<handle>/...` claimable by any room member (the only namespace where local and remote claims legitimately intersect), `local/...` claimable only by `home == "local"`, `<home>/...` only by that peer (and `home` is hub-derived, never claimant-chosen). Hub validates NFC canonical form, no dot segments, a 256-byte key cap and 16 keys per claim (both limits proposed by the boundary gap analysis in this wave, sized to bound hub-side validation cost; they trace to no external source and are free to move at spec time), prefix intersection. `task_conflict` returns the blocking key as an opaque stable digest when the refused claimant is non-local and the blocker is `local/...`, so back-off is implementable without disclosing pack layout. The spec states who validates what: semantic truth of keys is enforced at the mutation path for local members only; a peer's keys outside `room/...` are unverifiable declarations whose sole effect is board-side intersection refusal.

**Fairness needs shipping, not designing.** `max_claims_per_member` and `task_actions_per_min` are specified and measured absent (Appendix F 5.1 row: one member held 4 concurrent claims and ran 22 unthrottled mutating calls); both land before any remote claimant, with rate windows keyed per RFA-0.6 sect 5.6 so rejoin does not reset them. The composed attack to watch is state-shaped, not rate-shaped: one peer claims everything free (holding costs one idle long-poll), flaps offline, and `max_attempts` default 1 converts the whole board to privileged-pickup-only with no alert firing on a quiet room. The watch is N offline-releases from one `peer_id` in a window, surfacing to the operator and MAY auto-`hold_member`; `max_attempts` 1 itself stays untouched, its cross-org side-effect honesty is correct. A local-member claim head start is PARKED (trigger: first measured claim-race loss to a guest).

**Memory gains a principal axis.** No memory write carries a `home` today, no read path filters by requester, and parallel conversations turn the sequential cross-org leak into a same-instant relay through /memories that no operator hold can interpose on. Amendments to [04]: provenance gains hub-derived `requester_home` and room on every write attributable to a run; /memories writes from non-local-attributed runs are quarantined out of other turns' retrieval until the consolidation lane promotes them (mirroring the existing gate posture: defer, review, admit). Full per-home partitions stay PARKED (trigger: the first counterparty whose written agreement requires data separation); the room is the isolation unit and admission is the control.

**The local-only guarantees list, one normative paragraph for the wire spec** so no integrator infers a cross-org guarantee from a local mechanism: (1) resource-claim fencing at the mutation path: local members only; (2) semantic validity of resource keys: local only; (3) chain-id cycle refusal: conforming clients only; the cross-org guarantee is the reply_by clock; (4) turn serialization and one-writer-per-session: local resident runtime properties; the hub's only concurrency promise to a peer is one owner per (task, attempt), fenced; (5) the account cap and lane reserves: local compute governance; per-peer budgets are budgets, not concurrency caps; (6) memory write topology and consolidation ordering: local packs; (7) per-conversation FIFO: a local serve-loop property, a peer observes hub `seq` order only; (8) restart survival of the claim token's secret half: nobody's, by design; grants, unlike tokens, persist on the task. Plus one INTEROP sentence: a hub restart invalidates outstanding claim tokens, recovery is the still-valid membership or re-claim. One verification task carries over: whether the claim-revert ordering fix of RFA-0.6 sect 8.3 item 3 actually shipped with v0.6.3a needs a code check (the status table names its siblings and not it, and the never-infer-absence rule cuts both ways).

## 9. The runtime model: cycles, leases, approval cards, the dispatcher, and the new rung

**Reentrancy.** A asks A, or A asks B asks A, deadlocks unread today until `reply_by` (120 s of dead air): the serve loop is doubly serial, requests are not merely queued behind the turn lock but unread during a turn. Orleans-style interleaving admission is REJECTED (the turn's mutable state is the session transcript, which admits one writer; Orleans measured about 20 percent cost just for chain tracking; reopen only if the SDK ships concurrent turn injection into one session). What transplants is detection: a chain id on every ask as an envelope ext key plus hop depth (cap 8; Dapr defaults 32), and a resident blocked on that chain refuses an incoming request on it immediately with `would_deadlock` [05]. Turn-splitting continuations (Akka's tell-don't-ask) stay PARKED (trigger: field evidence of legitimate deep chains).

**Approval cards get consumption semantics before any parallelism ships.** CapLease measures the base rate: 39.8 percent of uncertain execution outcomes induce a semantically equivalent re-proposal of an already-authorized action, and fresh per-call approval does not help because the retry legitimately earns a fresh card; RFA has no canonical action identity across cards and no idempotency contract behind them, so the human is the ledger. Resume Means Resume supplies the placement constraint the mechanism must obey: per-process sequencing of the consumption ledger does not compose (cross-process double-fire 10/10 on every durable backend, window as wide as the gated node's execution, no ceiling below k=16, and the write-path gate repair was built and falsified), so the consumption record lives in a shared durable store and is claimed by a uniqueness-constraint INSERT at the durable-state read path, before execution. Atomix adds the field: cards carry an effect class, and irreversible effects gate until settlement rather than compensate after (0/500 leaked sends versus Saga compensation's 400/500); the SagaLLM compensator shape remains the fallback for reversible-with-cost effects [06]. Spec impact: RFA-0.5 approval-card clock section.

**The dispatcher.** Probe B settles rung-2 feasibility; the dispatcher replacing the doubly-serial `serve()` loop was NOT designed in this wave and is the first design task of ladder rung 3: per-conversation FIFO queues (the ordering Ray documents you silently lose otherwise), a sessions-map get-or-resume step that enforces one writer per session id, backpressure, and reply_by-aware admission, refusing or shedding a queued request that would expire before it starts. Lane priority inside the process stays PARKED (the account layer already has per-lane reserves; the in-process FIFO lock is where the inversion lives; trigger: a measured serve-latency incident). Lease grant-order policy (Autellix's attained-service shape, refined by Continuum) stays PARKED on rung 3+ shipping plus measured starvation, with the zero-traffic rule attached to any starvation meter.

**The new rung: candidate parallelism.** N independent runs of ONE task in N scratch surfaces that never merge, one output selected, the rest deleted: no shared-state conflict by construction, and the selection step is a verification act by a member that did not generate the candidates (wire 10.4). Written into the spec honestly: expect to lose 10-15 points of coverage to selection without an executable check (CodeMonkeys); when any verified completion is acceptable, early-stop needs no selector and buys 1.6-2.2x latency at 1.7-2.6x cost (M1-Parallel); identical packs produce useful candidate spread (DEI intra-agent diversity; M1-Parallel's diversity-prompting null) [06].

**Replicas-as-distinct-members** stays the zero-mechanics wide-scaling shape (Manus Wide Research) with the Orleans stateless-worker rule adopted as policy: multiple activations of one logical identity with no state reconciliation are legitimate only for stateless or read-only roles; a writing replica pair needs a memory merge story before it exists, and none ships anywhere [01][04][05]. Conversation affinity across replicas: PARKED (trigger: first multi-replica deployment; Temporal sticky-execution shape, and the checkpoint `{claude_session_id, room_cursor}` is already the replay anchor).

## 10. The concurrency testing rung

Every repo gate is serial, and the wave's own trigger was a race that only surfaced live; the one genuine concurrency probe in e2e (two concurrent claims) currently passes trivially because the claim path has no await between check and write, which is exactly the property rung 7's intersection check will break. The rung, from the dedicated gap analysis:

1. **Deterministic interleaving tests at four seams**: a test-only awaitable hook between check and commit in the store's claim path (undefined in production, so the await never yields), driving every ordering with barriers and asserting one winner, `task_conflict` for the loser, one token per (room, task, attempt); direct call-order enumeration over the synchronous memory verbs (pinning `strReplace`'s loud-stale contract, and the test for `create()`'s clobber exists first as the spec of the fix); two-connection races on lease admission (row count never exceeds the cap in any ordering); a never-two-turns-one-session property on the resident session map. Effort 2-3 days.
2. **One e2e scenario, two asks against one pack**: today assert strict serialization and per-ask run-id billing (a regression canary for the 2026-08-25 lease-race class); when pack concurrency lands, flip to overlap-allowed with invariants (lease cap held during the overlap, distinct session ids, no torn memory files, retrieval sets citing only each turn's own start state, which composes with section 6's HEAD stamp). Make the overlap reliable with one deliberately slow ask, not sleep tuning.
3. **A rule, not a new gate**: diffs touching the named concurrency surfaces (turnlock, account leases, the memoryfs write path, the session map, the claim path, knowledge sync) run the already-required SECOND parity pass under parallel load (one slow ask held in flight). Same two parity runs, one under load. Stress loops stay out of `npm test`; nondeterministic stress in the trust-anchor gate erodes it; an opt-in e2e:full-style mode is the home for soak repetition.
