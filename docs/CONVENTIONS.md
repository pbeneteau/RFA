# Conventions

> Observed code conventions in agent-com, derived from the source. Descriptive, not aspirational: every rule cites a real example. Generated by Kontrua; every claim is verified against the code at each update.

## Naming

- Lane types use string union literals declared as `export type Lane = "serve" | "schedule" | "background"`
- Constants that are re-exported from another module keep their original name, e.g. `EFFECTIVE_DEFAULT_CAP` re-exported from `src/hubdir.ts` via `src/account.ts`
- Extension wire keys follow reverse-domain notation, e.g. `"io.github.pbeneteau/action-identity"` assigned to `ACTION_IDENTITY_EXT`
- Boolean predicate functions are prefixed with `is`, e.g. `isRateLimitError` and `isAuthError` in `src/account.ts`
- Admission result interfaces use noun phrases, e.g. `Admission`, `Lease`, `Settlement`, `BudgetRequest` in `src/account.ts`
- Effect class values are lowercase kebab string literals: `"irreversible"`, `"reversible_with_cost"`, `"reversible"` collected in `EFFECT_CLASSES`
- Private class fields use the `private` keyword rather than `#` syntax, e.g. `private db: Database.Database` in `AccountLedger`
- Duration constants are suffixed `_MS` for milliseconds, e.g. `LEASE_TTL_MS`, `UNPARK_GRACE_MS`, `RATE_LIMIT_PAUSE_FLOOR_MS`
- The identity prefix encodes the normalization version as a string literal `"act1_"` prepended to the hex digest in `actionIdentity`

## File Organization

- Core runtime modules live directly under `src/`
- CLI entry point and command modules live under `src/cli/`
- CLI subcommands are individual files under `src/cli/commands/`
- TUI components are TypeScript/TSX files under `src/cli/tui/`
- Eval pipeline modules live under `src/evals/`
- MCP server integrations live under `src/servers/`
- All test files live under `test/` and are named `*.test.ts` or `*.test.tsx`
- Operator scripts (e2e, coldstart, proofs) live under `scripts/`
- Wire and platform specifications live under `spec/`
- Seed templates for hub directory initialization live under `templates/`
- The interoperability reference client lives at `interop/rfa_min.py`

## Imports & Modules

- Node built-ins are imported with the `node:` protocol prefix, e.g. `import Database from "better-sqlite3"` alongside `import { randomBytes } from "node:crypto"`
- The project uses ES module syntax (`"type": "module"` in `package.json`) with `.js` extensions on local imports in compiled output, e.g. `from "../src/proc.js"`
- Internal modules are imported by relative path with `.js` extension as required by Node16 module resolution, e.g. `from "../src/egress.js"` in `scripts/egress-proof.ts`
- `tsconfig.json` sets `"moduleResolution": "node16"` and `"module": "Node16"`, enforcing explicit extensions on relative imports
- The `@modelcontextprotocol/sdk` client is imported from its scoped subpath, e.g. `from "@modelcontextprotocol/sdk/client/index.js"`
- JSX is compiled with `"jsx": "react-jsx"` in `tsconfig.json`, used by TUI components under `src/cli/tui/`

## Error Handling

- Domain errors are typed classes extending `Error`, e.g. `RfaError` in `interop/rfa_min.py` carries `code`, `message`, `retry_after_s` and `data` fields
- `HubDirError` is caught by name and its `.hint` field is printed before `process.exit(2)`, e.g. in `scripts/repair-obs-cost.ts`
- Admission refusals are typed via the `reason` discriminant on the `Admission` interface: `"account_paused"`, `"cap_reached"`, `"budget_exhausted"`, `"maintenance"`
- Auth failures are detected by `isAuthError` using a shared `AUTH_FAILURE_RE` regex derived from `AUTH_FAILURE_MARKERS`, so the resident and the observability alert cannot classify the same error differently
- Rate-limit detection is centralised in `isRateLimitError` in `src/account.ts` and matched by `RATE_LIMIT_RE`
- Mutating RPC calls in `interop/rfa_min.py` are not retried blindly; only idempotent reads listed in `IDEMPOTENT` are retried with bounded jitter
- Process exit codes are explicit: `process.exit(1)` for operational failure, `process.exit(2)` for bad arguments or missing hub directory

## Testing Patterns

- The test runner is Node's built-in `--test` flag, invoked as `node --import tsx --test test/*.test.ts test/*.test.tsx`
- A `pretest` script guards the minimum Node version before any test file loads
- End-to-end scenarios are in `scripts/e2e.ts` and run via `npm run e2e` or `npm run e2e:full`
- Live fence behaviour is proved by `scripts/fence-proof.ts`, run via `npm run fence-proof`
- Live egress behaviour is proved by `scripts/egress-proof.ts`, run via `npm run egress-proof`
- TUI smoke tests are driven by `scripts/tui-drive.py` via `npm run tui:smoke`
- The eval reliability gate runs via `npm run evals` or `npm run evals:judged`
- Concurrency interleaving tests live in `test/interleaving.test.ts` and use barriers rather than timing
- The write-fence deterministic half lives in `test/writefence.test.ts`
- Hub directory path-resolution is regression-tested in `test/hubdir.test.ts`

## Logging & Observability

- The observability store is a SQLite database accessed via `better-sqlite3`, with a separate `runs.db` for engine runs and an obs DB for cost rows
- Spend attribution is written to `lease_settlements` with columns `lease_id`, `agent`, `lane`, `run_id`, `spend_day`, `ceiling_usd`, `actual_usd`, `acquired_at`, `settled_at`
- Rate-limit events are recorded to `account_rate_limits` with `agent`, `run_id`, `detail`, `at` and `handled` columns
- Auth failure markers are defined as `AUTH_FAILURE_MARKERS` in `src/account.ts` in SQL LIKE syntax and compiled into `AUTH_FAILURE_RE` for runtime use
- The `AccountSnapshot` interface exposes `in_flight`, `parked`, `by_lane`, `by_agent`, `paused_until`, `pause_reason`, `leases` and `maintenance` for operator inspection

## Inconsistencies

Axes where the codebase is inconsistent, and which variant dominates:

- Script language is inconsistent: operator scripts are TypeScript (`scripts/e2e.ts`, `scripts/fence-proof.ts`) except the TUI driver which is Python (`scripts/tui-drive.py`)
- Retry logic style differs between layers: `interop/rfa_min.py` uses an explicit `RETRY_DELAYS_S` list with bounded jitter, while `src/account.ts` uses a `UNPARK_GRACE_MS` polling approach with no shared retry abstraction
