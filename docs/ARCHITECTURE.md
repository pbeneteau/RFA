# Architecture

> System-level view of agent-com: how it is organized and how the pieces fit together. Generated by Kontrua; every claim is verified against the code at each update.

## System Context

The system is a self-hosted hub where local and remote AI agents collaborate in rooms over MCP. The CLI entry point is `src/cli/main.ts`, which installs as the `rfa` and `agent-com` binaries from `dist/cli/main.js`. The hub process (`src/main.ts`) serves HTTP and persists state in a SQLite store under the hub directory's `.rfa/data/` path, using `better-sqlite3`. External services are reached through the Anthropic Claude Agent SDK and the MCP client and server packages declared in `package.json`.

## Module Decomposition

- `src/` - core runtime: hub, engine, dispatch, sessions, store, credentials, signing, egress, and all agent lifecycle modules
- `src/cli/` - operator CLI: routing, prompts, scaffolding, and command implementations that front every hub operation
- `src/cli/commands/` - individual CLI command modules (agent, connect, creds, dash, doctor, init, ops, room, server, talk, and others)
- `src/cli/tui/` - Ink/React terminal UI components including the dashboard, onboarding wizard, agent editor, and palette
- `src/evals/` - evaluation pipeline: runner, judge, gate, parity, label, promote, trajectory, and concurrent eval modules
- `src/servers/` - MCP server integrations (Linear)
- `src/hub.ts` - hub HTTP server
- `src/engine.ts` - agent run engine
- `src/dispatch.ts` - task dispatch
- `src/supervisor.ts` - process supervisor for resident agents
- `src/writefence.ts` - two-door write fence keeping `Write`, `Edit`, and `NotebookEdit` out of `allowedTools` for every pack
- `src/fenceprobe.ts` - live deny probe run at every boot to re-prove write-fence fall-through per guarded built-in
- `src/egress.ts` - egress and declared surface enforcement
- `src/toolclass.ts` - tool classification including the `fenceApplies` coverage predicate
- `src/hubdir.ts` - the single module that resolves paths onto the hub directory
- `src/proc.ts` - child-process spawning via `spawnEntry` and `stopTree`, used instead of `npx`
- `src/procscan.ts` - process-table scanning to locate residents without substring matching
- `src/secrets.ts` - transport credential resolution via `transportToken()`
- `src/signing.ts` - log signing
- `src/logverify.ts` - log verification
- `src/knowledge.ts` and `src/knowledge-sources.ts` - knowledge source tracking and sync
- `src/mcplaunch.ts` - spawns MCP servers of the `command` and `builtin` forms through srt, one instance each per server's own sandbox block
- `src/mcpsandbox.ts` - MCP sandbox configuration
- `src/memoryfs.ts` - memory filesystem
- `src/consolidate.ts` - memory consolidation
- `src/candidates.ts` - candidate fan-out for parallel task runs
- `src/turnlock.ts` - turn lock enforcing the serial-loop invariant
- `src/account.ts` - account and budget ledger
- `src/obs.ts` - observability
- `src/bridge.ts` - room bridge
- `src/posture.ts` - exposure posture
- `src/principals.ts` - principal identity
- `src/credentials.ts` - credential management
- `src/migrate.ts` - hub directory migration
- `interop/rfa_min.py` - minimal Python interop reference implementation
- `scripts/` - operator scripts: e2e, coldstart, demo-push, fence-proof, egress-proof, watchdog-replay, tui-drive, repair-obs-cost
- `spec/` - RFA specification documents (versions 0.1 through 0.9)
- `templates/` - files seeded into new hub directories by `rfa init`, including the eval rubric, service definitions, and skill templates
- `console/` - web console static assets

## Data Flow

An operator request enters through `src/cli/main.ts`, which routes to a command in `src/cli/commands/` or the TUI in `src/cli/tui/`. Commands that need hub state open the store via `src/hubdir.ts` when no hub is running, or call the hub's HTTP API when one is. A task dispatched through `src/dispatch.ts` is picked up by `src/engine.ts`, which launches a resident agent process via `src/proc.ts` and `src/mcplaunch.ts`; the resident's writes pass through the two-door fence in `src/writefence.ts` and `src/fenceprobe.ts` before reaching `src/memoryfs.ts` or the run scratch surface. Observability events flow through `src/obs.ts`, and the completed run's episode is available to the eval pipeline in `src/evals/runner.ts`.

## Cross-Cutting Concerns

- Transport credential resolution is centralised in `transportToken()` in `src/secrets.ts`; callers read `RFA_TOKEN` per call, never at import time
- Child-process lifecycle is managed through `spawnEntry` and `stopTree` in `src/proc.ts` to ensure SIGKILL propagates to the process group
- Write-fence enforcement is applied at startup by `src/writefence.ts`, which keeps `Write`, `Edit`, and `NotebookEdit` out of `allowedTools` for every pack
- Boot-time fence probing is performed by `src/fenceprobe.ts`; `bypassed` and `inconclusive` results are both fatal
- Tool surface classification uses `fenceApplies` in `src/toolclass.ts` to determine whether the write fence applies (any built-in of class `guarded` or `command`)
- Log integrity is provided by `src/signing.ts` (signing) and `src/logverify.ts` (verification)
- Observability is collected in `src/obs.ts`
- Error types are centralised in `src/errors.ts`
- Background knowledge sync takes a drain barrier in the account lease table before pulling, coordinated through `src/account.ts`
- The eval reliability gate is run with `npm run evals`
- The parity gate is run with `npm run parity`
- The write-fence proof is run with `npm run fence-proof`
- The egress proof is run with `npm run egress-proof`

## Infrastructure & Deployment

- `templates/service/launchd.plist` - launchd service definition for macOS deployment
- `templates/service/systemd.service` - systemd service definition for Linux deployment
- The `build` script compiles TypeScript sources from `src/` to `dist/` via `tsc`
- The `engines` field in `package.json` requires Node.js `>=22`
- The `pretest` script enforces Node.js major version 22 or above before running tests
- The `coldstart` script (`npm run coldstart`) packs, installs into a fresh prefix, and answers one question to validate end-to-end packaging
